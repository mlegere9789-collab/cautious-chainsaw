### 1.1 The browser harness (state of the working tree, not yet committed when read)

`app/tests/lib.mjs` in the working tree has environment switches that a gate runner calling the specs has to know: `BT_GL=auto|gpu|software` (auto tries the hardware flags and falls back to SwiftShader), `BT_API=webgpu|webgl2|auto`, `BT_DIST=<folder>` (serve a packed dist instead of the source tree), `BT_OUT=<name>` (numbers and pictures go to `app/tests/results/<name>/`; on a software renderer the default is `results/sw-latest/`), `BT_WAIT_K` (debugging only). Its `test` wrapper adds `t.gpuOnly(label, fn)` and `t.notRun(reason)`: on a software renderer the wrapped assertion is not evaluated and the run prints `# NOT RUN (NEEDS_GPU): <label>`. So a spec can end green here with parts not run: a gate runner must read those lines and count such a test as not run for the part it names, never as passed. A folder `app/tests/results/sw-round-1` existed at 19:1x UTC. The browser specs were not run for this note (their owner was running them through the lock).
