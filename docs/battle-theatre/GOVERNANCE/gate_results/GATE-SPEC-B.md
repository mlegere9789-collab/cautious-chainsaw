### 1.1 The browser harness (`app/tests/lib.mjs`; the working-tree version of the first writing was committed at 19:11 UTC)

`app/tests/lib.mjs` in the working tree has environment switches that a gate runner calling the specs has to know: `BT_GL=auto|gpu|software` (auto tries the hardware flags and falls back to SwiftShader), `BT_API=webgpu|webgl2|auto`, `BT_DIST=<folder>` (serve a packed dist instead of the source tree), `BT_OUT=<name>` (numbers and pictures go to `app/tests/results/<name>/`; on a software renderer the default is `results/sw-latest/`), `BT_EXTRA=a=b&c=d` (more address parameters for every page a spec opens), `BT_WAIT_K` (debugging only). Its `test` wrapper adds `t.gpuOnly(label, fn)` and `t.notRun(reason)`: on a software renderer the wrapped assertion is not evaluated and the run prints `# NOT RUN (NEEDS_GPU): <label>`. So a spec can end green here with parts not run: a gate runner must read those lines and count such a test as not run for the part it names, never as passed. The owner of the specs runs them one after another through `tmp/bt-spec/runq.sh` and logs each run under `app/tests/results/sw-round-1/` (`runs.tsv` and one `.log` per spec); those logs are that engineer's, read here and not reproduced. The first logged run, `webgl2.spec.mjs` at 19:13 UTC on HEAD 1a8dd154, ended `not ok` after 352 s on a console line "Failed to load resource: the server responded with a status of 404 (Not Found)" (the log does not name the request that failed; it records that `app/src/ext/index.mjs` changed during the run); the next, `sky.spec.mjs`, had printed its day and night luminance numbers when its log was read at 19:27 and had no end line yet. The same logs give what a frame costs on this container's software renderer with the placeholder crowd: 3.9 s (webgl2.spec) and 5.2 s (sky.spec) per frame, 5.5 s p50 at 165,000 soldiers and 1280 x 720, entry 18 to 26 s, so the specs scale every wait by a measured factor K of 39 to 52.
