The test files together hold 585 test methods in 14 files; the fixtures are `gates_fixtures.py`, `pq_fixtures.py`, `pq_world.py`, `q03_world.py` and `q456_fixtures.py`. A test of the first kind feeds a runner a synthetic dump of the layer or a synthetic table and asserts that each injected defect turns the right check red; a test of the second kind (`RealData`, `RealProduct`, `SceneChild`) runs the real node child on the real history layer, world and stage and writes into a scratch folder; a third kind injects a defect into the REAL code path with `--mutate FILE.mjs` (the module exports `mutateRaw`, `mutateLayer`, `mutateWorld`, `mutateStage` or `afterLoad`; 14 modules in `q456_mutations/` for Q04 to Q06) and asserts that the real child's verdict changes. The mutation checks (`mutation_check*.py`) copy `tools/bt/gates`, disable one check in the copy and require a unit test to go red: the stored text of Q01, Q14 and Q20 reads "caught 48 of 48" (00:39 UTC on 16 November); the mutation checks of Q03 and Q04 to Q06 exist and were not run at this pass.

**The record and the conventions, as implemented** (`lib/pq_common.py`, GATE-SPEC 1.6). Schema `bt-gate-result/1`; header keys `gate`, `run_id`, `started_utc`, `finished_utc`, `command`, `tool_versions`, `renderer_class` (`python`, `node` or `mixed` for the runners here; no runner has a browser or GPU part), `runnable_here`, `inputs` (path, bytes, role and sha256 of every file read, with `missing: true` for an input that is absent), `input_hashes` (the same as a map), `thresholds` (id, value, decision, metric), `scenario_set` and `time_grid` where they apply, `counts` and `totals` (per check and per result), `verdict` (PASS, FAIL or INCOMPLETE), `incomplete_reasons`, `owed`, `notes`, and `items` (id of the form `Qnn/Qnn.k/<subject>/<scenario>`, `check`, `pass`, `result`, `reason`, `evidence`, and where they apply `subjects`, `sub_requirements`, `scenario`). The result words are PASS, COVERED, FAIL, NOT-RUN, BLOCKED-INPUT and N/A; `pass` is true only for PASS; an item whose input is missing is BLOCKED-INPUT with a reason that begins "input missing:", never a pass; items, evidence lists and totals are sorted so that two runs on the same inputs give identical items and the clock lives only in the header. A runner writes `<out>/Qnn.json`, replaces the one before as `<out>/Qnn.prev.json` and puts sidecars in `<out>/evidence/Qnn/`; `--out DIR` redirects all three, `--no-write` prints only; it never writes a `passes` flag. Exit codes: 0 PASS, 1 FAIL, 2 INCOMPLETE, 3 runner error (nothing is written then, so a good earlier record is not clobbered). `sub_requirements` is on every item of Q01, Q14 and Q20 (Q01: R04.0000 and R10.0000; Q14: R03.0000, R04.0000 and the R13.G rows; Q20: R04.0000 and R16.0000), on 45 of the 253 items of Q25 (the 45 R12 rows), and on NO item of Q02, Q19 or Q23 (found at pass 6): a later step that sets `passes` per row has to map those items to rows by gate and class (for example the conflict items to the 47 `R03.C` rows), which no code does yet.

**What does not exist** (checked at 02:3x UTC): `run_gate.py`, `run_all.py`, `apply_passes.py` and `milestone.py` of GATE-SPEC 1.6 (the last stage of the workflow `bt-gate-engine.mjs` writes `run_all.py` and `apply_passes.py`), `GOVERNANCE/gate_results/thresholds.json` and `SUMMARY.md`, a runner for each of Q07 to Q13, Q15 to Q18, Q21, Q22, Q24 and Q26 to Q28 (17 gates), and a stored result for Q03 to Q06: the dense runs of Q04, Q05 and Q06 over S* (333 scenarios in 10 interaction groups) were queued behind the machine lock on 16 November at 01:24 and 01:47 (`tmp/bt-gates/q456/run_q04_full.sh`, `run_q05_full.sh`, `run_q06_full.sh`, from frozen copies of the runners under `snap1/` and `snap2/`) and their logs are empty: the owner's full pause at 01:53 UTC stopped every workflow and the leftover jobs (`horde/CAMPAIGN.md`), and the container restarted at about 02:20 UTC. No runner reads `thresholds.json` (it does not exist): each carries its constants and records them as `thresholds` in its own record (T-Q02-1 14 words, T-Q05-1 1.0 m, T-Q05-2 1.0001, T-Q06-1 90 s), so GATE-SPEC 1.7's rule that a threshold with no decision id makes a gate INCOMPLETE is not applied by any code.

**Findings about the runners at the sixth pass** (a specification pass changes no code; each is for the runners' owner, which is this workstream's later stages). (1) `q19_claims.py` and `q23_marking.py` insert only `tools/bt/gates/lib` on `sys.path` and import `q02_provenance` from the folder above it, so `python3 -I tools/bt/gates/q19_claims.py` fails with `ModuleNotFoundError: No module named 'q02_provenance'`; started as a script they work, and the other nine runners insert their own folder and run under `-I`. (2) The same property, Q23.7 (a non-documented register entry has a marking), is counted differently by `check_coverage.py` (10 of 385) and by `q23_marking.py` (11 of 385): the first treats only `-`, `none` and the shard-proposal marker as an empty marking, the second also `n/a`, which EG-0006 carries. (3) The end-to-end tests read the working tree: they passed between 02:40 and 02:54 UTC and can go red when another workstream changes the code or data they exercise, so a red `RealData` test is read as in 5.4. (4) `test_q03.py` is heavy (117 tests, 490 s of wall time and 128 s of CPU at a load of 20 to 30, run alone); the other thirteen files need 0.07 to 39 s of CPU each (the Q04 file 34.6 s when run alone and 38.9 s in the light run). (5) The runners hash the data and the application code they read but not their own source: a record does not say which version of the runner made it (`lib/extracts.py`, which Q01, Q02 and Q14 import, was modified at 00:41:19 on 16 November, after the Q01 record finished at 00:36:33 and the Q14 record at 00:35:41). (6) A re-run into the default folder replaces the stored record and its `.prev.json`; experiments use `--out`.

**What a runner for one of the other 17 gates can reuse** (names read from the files at 02:5x UTC). `lib/pq_common.py`: `Env` (the root, `--out`, `p()` and `btp()` path helpers, so that a test can hand a runner a scratch tree with the same layout), `Record` (items, thresholds, owed, notes, counts, verdict, the atomic write of `Qnn.json`), `InputMissing`, `sha256_file`, `is_placeholder`, `run_node`, `base_parser`, `finish_cli` and `guarded_main` (the exit codes). `oobgates_common.py`: `layer_dump` (runs a node child that builds the real layer and returns its JSON dump, a failed child being exit 3 and never a pass), `gate_rows` and `sub_requirements_for` (the rows of `requirements.json` an item bears on, with the population rows `R10.U-<unit>` and `R17.U-<unit>` once they exist), `register_state` and `covered_by_register` (whether a register entry exists, is open, has its eleven fields and `owner_q` and a dated search log: the L3 test of GATE-SPEC 1.4). `lib/extracts.py`: `fold`, `numbers_in_span`, `quote_ok` and `TextStore` (the one function that finds a source extract again in the stored text, with `no_text` where the text is not on the machine). `lib/datum_scan.py` with `datum_classes.json` (55 datum classes read into normalised datums) and `lib/loadlist.py` (the page's load list). `q456_lib.mjs` (the real layer, world and stage, the scenario set S*, the time grid, the `--mutate` hook and the list of every file the run read). For the hooks that already exist as pure functions (`checkVegetation`, `checkScene`, `checkLaterMemorials`, `checkRun`, `checkCompare`, `selectFigures`, `state_at`, `gate_q11`, `gate_q22`) a runner is a thin wrapper that calls them and wraps each result in items; `app/docs/GATE-HOOKS.md` and 3.2 list them.
