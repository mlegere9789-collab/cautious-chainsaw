# Source ledger: the research of the 47 source conflicts (C-001..C-047)

Written for the resolution files `docs/battle-theatre/GOVERNANCE/conflicts/resolutions/C-0xx.json` and read by `tools/bt/conflicts/validate_resolution.py`, which takes the source classes, the local text paths, the hashes and the page model of every citation from the tables of this file (through the engine of `tools/bt/town/validate_evidence.py`: `parse_ledger`, `check_cite`). Seeded by `tools/bt/conflicts/build_sources.py` on 2026-11-16 from the town ledger (read only), the library indexes `GOVERNANCE/library/acquired*.json` and the files on disk; every hash below was computed from the file.

## 1. How a citation uses this ledger, and how to add a source

- `id` is what a citation writes in `source`. `class` decides what the source may do: **primary** (made in 1863-1869 by a witness or an official actor, or a page of a paper of 1863, or a compiled Official Records volume), **official** (a Park Service, Library of Congress or National Archives record), **book** (any later published account, public domain), **lead** (a web page, an encyclopaedia, a forum, a blog, a project working file: it points to a primary source, it never proves; a lead cannot make a value documented or inferred, and a default never rests on a lead alone).
- `text` is the repository-relative path of the local text the quote is matched in. A path with `{part}` is a family of texts (one issue, one newspaper page): the citation names the part. `-` means there is no local text: the source cannot be quoted yet.
- `pages` is the page model: `or27` (Official Records vol. 27: the citation's `part` is a record id of `docs/battle-theatre/library/or27_index.json`, e.g. `OR27-1-R006`, and `page` is the printed page of the scan leaf, DD-TL02-04 item 4); `markers` (the text carries `=== PAGE n ===` lines: `page` is that n, the PDF page index, and `printed_page` may carry the printed number); `none` (the text has no page marks: `page` is the printed page as read in the text or on the page image, or null with `page_note`).
- Offsets are character offsets into the file decoded as UTF-8 with `newline=''` (the convention of `tools/bt/or27_lib.py`). `tools/bt/or27_find.py` prints them for the Official Records; `tools/bt/conflicts/find_passage.py` prints them for every other text of this ledger.
- `kind` is the usual kind of writing of the source (order_or_dispatch, official_report, private_letter_or_diary, newspaper_1863, early_narrative, postwar_narrative, later_history, proceedings_or_tablet, reference_table, institutional, lead, mixed). It is a hint: the citation's own `written` block states the date and kind of the passage, because one book holds several (the letters in Meade's Life and Letters were written in 1863; the narrative around them in 1913).
- **To add a source** (a text you fetched, or a source of the town ledger or the life registry you want to cite): run `python3 -I tools/bt/conflicts/add_source.py --id NEWID --class primary|official|book|lead --title "..." --author "..." --date "..." --text tmp/library/conflicts/<C-0xx>/<file>.txt --url https://... --kind <kind> --notes "..."` (it computes the hash, the page model and the format, refuses a duplicate id or a path that is already in the ledger, and appends one row under the marker line of section 10 under a file lock). `--from-town ID` adopts a row of docs/battle-theatre/town/SOURCES.md, `--from-life ID` a row of life/evidence/sources.json. Downloads go under `tmp/library/conflicts/<C-0xx>/` with at most one request per second; the ledger row carries the url and the date fetched in `notes`. A hand-written row is allowed only as a single shell `>>` append of one complete line under the marker; never rewrite the file.
- Public sources only, one request per second, no login, no CAPTCHA, no bot-block circumvention; a refusal is recorded in a failed lookup, never worked around.
- `python3 -I tools/bt/conflicts/build_sources.py --check` re-hashes every local text of this ledger.
