# Browser verification list: the vegetation of July 1863 (requirement R20, gate Q21)

What has been run, and on what, is written in `VEGETATION-NOTES.md` section 6 and in `GOVERNANCE/horde/ws-world/veg-status.md`: node tests of the data, the state function, the meshes, the plan of the troops' walk, the wind, the scene check and the module on a stand-in theatre with a recording graphics context; the browser harness `app/tests/vegetation-browser.mjs` on a software renderer (SwiftShader) in a headless Chromium. **Nothing in this list has been run on a real GPU, in another browser engine, with a screen reader or on a phone, and no frame time has been measured.** Each row is owed until a dated line in `GOVERNANCE/progress.md` says it was run and what came out.

| id | check | how | pass |
|---|---|---|---|
| VEG-A1 | Frame cost with the layer on and off, the standing crop on and off, and after the choice of the dense understory (84,000 more instances) | the five cases of `app/tests/perf.spec.mjs` with `?veg=off` and without it, then `?vegshell=on`, then `CF-VEG-UNDER` set to `dense`, through `tools/horde/bench.sh --timing` on a machine with a GPU | the frame time of each case is recorded; the gates of the performance budget hold with the layer on at its default; the cost of each extra is written down |
| VEG-A2 | The first frame after choosing an understory reading: the woods are placed again (about a second of work in node) | `btApp.theatre.vegetation.choose('CF-VEG-UNDER', 'dense')` and `performance.now()` around the next two frames, on a phone and on a laptop | no frame longer than the budget allows beyond the one frame that places the woods, and that frame is shorter than about two seconds; the page stays responsive (the panel closes, Back works) |
