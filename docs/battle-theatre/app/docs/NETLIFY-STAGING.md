# Battle Theatre: Netlify staging build

A separate, test-only site made from the current page shell. It is not the production site and nothing here is published by the build tool.

## Build
`node tools/bt/pack_theatre.mjs` writes `deliver/bt-staging/dist/` and `deliver/gettysburg-BT-staging-<hash>.zip` with a `.sha256` beside it (`deliver/` is not committed). The build is deterministic: the same sources give the same bytes, the same zip and the same 8-character hash. The hash is shown in the lower-left corner of the page ("Battle Theatre staging build <hash>") and is in `MANIFEST.json` (size and SHA-256 of every file). Self-test: `node --test tests/bt-pack/pack.test.mjs`. Real-run check of the packed site: `nice -n 10 node tools/bt/verify_staging.mjs --dist deliver/bt-staging/dist` (software WebGL2, one browser at a time; see "How the zip is checked").

## What the owner does
1. In Netlify, add a new site by dropping a folder or zip (labels on Netlify screens are from memory; if one differs, stop and ask). Drop the zip, or the unzipped `dist` folder, onto a **new throwaway site**, not the production site.
2. Open the address Netlify gives. The root page forwards to `/app/index.html`. Press the enter button on the landing page.
3. Send the address back so the checks can be run against it. Delete the throwaway site when done.

The site sends `X-Robots-Tag: noindex, nofollow` (and a robots meta tag) so search engines ignore it. The "Return to the map" link goes to the staging root, not to the main map.

## What is in the zip
The shell (`app/`: page, styles, 45 modules, 14 data files) and exactly the siblings it requests at runtime, found by tracing the module imports (static, `export ... from` and `import()`), every file URL in the code (`URLS.<folder> + 'file'`, template strings with a literal prefix, `new URL('relative', import.meta.url)`, `fetch('literal')`) and an explicit include list for the data the features load through a base path (`app/data/audio3d`, `app/data/anim3d`, `app/data/fx3d`, the figures' data), and confirmed by a real run's request log (no 404): the prototype renderers and terrain (`render/prototype/`), `sim/`, `GOVERNANCE/` (timeline, register index, conflicts), `environment/`, `history/`, `structures/`, `kit/`. The folder layout is kept so every relative URL works from the site root. Left out: tests, screenshots, notes, tools, and the files of the figures' data folder that no feature loads.
Files are not renamed with hashes (the modules import each other by relative path); `_headers` sets `Cache-Control: max-age=0, must-revalidate`, so the browser revalidates against Netlify's content ETag and unchanged files return 304. No COOP/COEP headers: the shell uses no SharedArrayBuffer.

## What works
- **WebGL2 is the default renderer** (delegated decision DD-27, reversible): the weather and the effects are drawn only on WebGL2, and the WebGPU picture has not been seen. `?api=webgpu` asks for WebGPU (the ribbon then says the weather and effects are not drawn); `?api=auto` asks for WebGPU first and falls back to WebGL2.
- Landing page, timeline and scrubber, scenarios for source conflicts (each of the 47 opens on its delegated default with its tier, labelled "Default chosen under delegated authority, reversible by the owner"; every other value, including the plan's, stays selectable; one button switches all to the plan's values), tier marking, evidence overlay, bookmarks, the real history layer (`?history=stub` opens the placeholder layer).
- The figures (`figures3d`, `anim3d`, `crowd`), the effects and weather (`fx3d`, `weather3d`) and the sound (`audio3d`) are wired into the shell and shipped; sound starts only on the owner's click. The sound marking default is the panel disclosure (DEC-001 option a, delegated).

## How the zip is checked
`tools/bt/verify_staging.mjs` opens the packed `dist` in a browser (software WebGL2, one at a time), enters the theatre with the figures on, starts the sound programmatically (what a click does), runs the scene for a few frames at 3 July 13:30, flies the camera to a unit, runs forward at 2x, goes to 4 July 15:00 and opens the Sources drawer. It then requires (1) every request to the packed site answers 2xx (zero 404s) and (2) every URL the same run loads from the source tree is present in the packed site. The packer's copy audit must report zero hits (it also rejects "generated by ... / do not edit by hand" style notes).
