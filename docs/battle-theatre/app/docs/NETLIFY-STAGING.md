## Build
- `node tools/bt/verify_staging.mjs --pack` is the whole honest run: it copies the tree to a snapshot (so that nobody's edit moves the target during the run), packs the snapshot (the zip and its `.sha256` go to `deliver/`, the dist to `tmp/bt-spec/verify/work/dist` so that a job that is serving `deliver/bt-staging/dist` is never disturbed), checks the dist and the zip (static checks, below), walks the packed site and the snapshot in a browser and compares them. Each walk also saves pictures (`tmp/bt-spec/verify/shots/<time>/dist-<nn>-<step>.png` and `source-...`; `--shots <dir>`, `--no-shots`, `--viewport 1280x720`) for a person to look at: the check itself does not judge a picture. Only a build that passes every check refreshes `deliver/bt-staging/dist`; `deliver/bt-staging/LAST-VERIFY.txt` says in every case what the last run found. On the shared machine start it through the lock: `tools/horde/bench.sh node tools/bt/verify_staging.mjs --pack --json tmp/bt-spec/verify/<name>.json` (a software frame takes seconds: on 2026-11-13, with the machine at a load of about 10, the two walks took 12 and 14 minutes; waiting for the lock took far longer; the walk now has three more steps, dawn, dusk and night, and a few more pictures). `--static-only --dist <dist> --zip <zip>` runs the checks that need no browser and no lock, in seconds.
- `node tools/bt/pack_theatre.mjs` is only the build (`--no-zip` for the dist alone, `--out`, `--zip-dir`; give it `--out` somewhere under `tmp/`, because the default folder `deliver/bt-staging/dist` is the one a verified build refreshes). It prints the bytes of the build by folder (`bytesByFolder`), so that the weight of a new section shows at once. It exits 2 and names the lines when the copy audit finds anything; the zip of such a build carries `-AUDIT-HITS-<n>` in its name. The zips of earlier builds that failed the audit are removed by the next pack; a clean zip is never removed.
- The build is deterministic: the same sources give the same bytes, the same zip and the same 8-character id. The id is shown in the lower-left corner of the page ("Battle Theatre staging build <id>") and is in `MANIFEST.json` (size and SHA-256 of every file). `deliver/` is not committed.
- Self-tests: `node --test tests/bt-pack/pack.test.mjs tests/bt-pack/verify.test.mjs` (the packer on the real tree and on a made-up one that holds every kind of load; the checks of the verification on made-up folders, made-up request logs and a made-up page for the pictures; about 20 s without a browser). Three of them read the real tree and are not loosened: "the shipped kit and data files carry no production note" and "copy audit of the shipped dist is clean" are the shipping gate (red while any shipped file says how it was made), and "real roster data: the printed names pass, nothing else in the 118 files is a hit" reads `rosters/data2` as it stands (red while its files, the index included, say how they were made). `BT_PACK_NO_BROWSER=1` skips the one test that starts a browser; otherwise run them through the machine lock.

## What the owner does
1. In Netlify, add a new site by dropping a folder or zip (labels on Netlify screens are from memory; if one differs, stop and ask). Drop the zip, or the unzipped `dist` folder, onto a **new throwaway site**, not the production site.
2. Open the address Netlify gives. The root page forwards to `/app/index.html`. Press the enter button on the landing page.
3. Send the address back so the checks can be run against it. Delete the throwaway site when done.

The site sends `X-Robots-Tag: noindex, nofollow` (and a robots meta tag) so search engines ignore it. The "Return to the map" link goes to the staging root, not to the main map.

## What is in the zip
The shell (`app/`: the page, its style sheet, every module of `app/src/` including the added layers in `app/src/ext/`, and the data files the modules load: `app/data/*.json`, four files of `audio3d/`, three of `fx3d/` and two of the figures' files) and exactly the siblings it requests at runtime: the prototype renderers and terrain (`render/prototype/`), `sim/`, `GOVERNANCE/` (timeline, register index reduced to the entry ids, conflicts), `environment/`, `history/`, `structures/`, `kit/`. The folder layout is kept so every relative URL works from the site root. The numbers of the current build are in the block at the top.

How the files are found (`tools/bt/pack_theatre.mjs`, header comment): the pages and their style sheets; the import graph of the modules (static imports, `import('literal')`, bare names through the import map, and computed imports with a literal folder prefix: `import('./ext/' + path)` takes the folder, and `src/ext/index.mjs` says which modules the page loads); every file address in the code (`URLS.<key> + 'file'`, the same through `ctx.urls.<key>` in an added layer, template strings with a literal prefix, `new URL('relative', import.meta.url)`, `fetch('literal')`, workers); a static section beside the shell (`app/roster`, when it exists: every page, script, style sheet and the files its index lists) and an explicit include list for the data the features load through a base path the scan cannot follow. A real run then confirms the result (next section). Left out: tests, screenshots, notes, tools, and the data files that no page requests: the rest of the figures' data folder, the animation catalogue files (`app/data/anim3d`) and six files of the sound and effects data folders (`MANIFEST.json` lists them under "leftOut"). The real run never asked for them, and a test fails the day a shipped module names one as a string outside a comment.

Files are not renamed with hashes (the modules import each other by relative path); `_headers` sets `Cache-Control: max-age=0, must-revalidate`, so the browser revalidates against Netlify's content ETag and unchanged files return 304. No COOP/COEP headers: the shell uses no SharedArrayBuffer.

## What works
- **WebGL2 is the default renderer** (delegated decision DD-27, reversible): it is the path whose weather and effects have been looked at most; the WebGPU path has been seen only on a software adapter, never on a real GPU. `?api=webgpu` asks for WebGPU; `?api=auto` asks for WebGPU first and falls back to WebGL2.
- Landing page, timeline and scrubber, scenarios for source conflicts (each of the 47 opens on its delegated default with its tier, labelled "Default chosen under delegated authority, reversible by the owner"; every other value, including the plan's, stays selectable; one button switches all to the plan's values), tier marking, evidence overlay, bookmarks, the real history layer (`?history=stub` opens the placeholder layer).
- The figures (`figures3d`, `anim3d`, `crowd`), the effects and weather (`fx3d`, `weather3d`) and the sound (`audio3d`) are wired into the shell and shipped; sound starts only on the owner's click. The sound marking default is the panel disclosure (DEC-001 option a, delegated).
- The added layers (the **More** tool, `app/src/ext/`, contract in `docs/EXT-CONTRACT.md`): the site's 512 later memorials as marks over the picture (off until switched on, labelled "later memorial", never part of the 1863 scene), the site's 16 tour stops as camera positions, and the vegetation of July 1863 (fields, woodlots, orchards and trees with a state by date and a tier; on at entry; `?veg=off` keeps it out). `?ext=off` skips the loader for one visit.
- **Dead links**: the "Open register entry ..." links of the unit card and the event panel lead to `GOVERNANCE/register/*.md`. The 820 working copies of those entries carry internal notes that the copy rules keep out of a published build, so the packer withholds them (listed in `MANIFEST.json`, "withheld") and the links answer 404 in this build. A request to the shell's owner is open (`GOVERNANCE/horde/requests/renderer-register-links-in-staging.md`).

## How the build is checked
`tools/bt/verify_staging.mjs` (the numbers of the last run are in the report it writes with `--json`):

1. **Static**: the dist equals its `MANIFEST.json` byte for byte and has no stray file; the zip holds exactly the dist (names, sizes, CRC-32), has no comment, its `.sha256` file is right, `unzip -t` passes, and its name carries the build id; every relative import, style-sheet address, link and import-map target of the dist exists; no README, note, source map, log or backup ships; every name can be unpacked by the owner's Windows and carried by a URL (no `<>:"\|?*#%`, no device name such as CON or NUL, no name ending in a dot or a space, no two paths that differ only by letter case, no path longer than 150 characters); the root page forwards to `/app/index.html`; and the data side of the theatre's start runs in node from the dist alone (timeline, conflicts, sky tables, bookmarks, terrain, the history data, the real history layer, the structure inputs, with `fetch` answering 404 for a file the dist lacks), which finds a missing data file in a second and without a browser.
2. **The packed dist is served the way Netlify serves it** (its `_headers` applied: content types, `nosniff`) and walked in a browser (software WebGL2, one at a time; the landing page and the steps that show something are photographed): enter the theatre with the figures, effects and structures on; wait for the added layers to settle; start the sound (open Settings and press "Start sound", the way a visitor does; the call of the audio host is the fallback when the button is not found, and the report says which one ran); 3 July 13:30; fly to a unit (the soldiers close up); play at 2x and at 60x; 3 July at dawn (04:30), dusk (19:30) and night (23:00); 4 July 15:00 (rain); open every drawer; select a unit; switch every added layer on, open every added panel, fly to a tour stop, switch them off; press Back. Then every page of a static section is visited, its links followed and its controls pressed (when the section exists).
3. **The same walk is made against the snapshot of the source tree**, and the two request logs are compared.
4. **The check fails** when any request to the packed site does not answer 2xx (zero 404s), when a URL the source run loaded is not in the dist (nothing missing), when a console or page error appears only in the packed site, when a step that passes at the source fails in the dist, when the sound does not start, when an added layer is in another state than at the source, when a section page does not load, or when the copy audit finds anything.

What a run of this kind cannot show is printed with every verdict ("NOT RUN here"): a real GPU (no frame time, long task or input delay is measured; software rendering shows pictures, not speed), the WebGPU picture, hearing the sound, other visits (`?history=stub`, `?ext=off`, `?crowd=off`, a phone-sized page, a second entry after Back), other browsers and real phones. Files that ship because the trace found a reference but that this walk never requested are listed in the report (`shippedNeverRequested`); they are covered by the trace and the static checks, not by the real run.

## Copy audit
The audit (no mention of how the site was made in any shipped file) covers the AI and tool names and also production notes. It reads text files line by line, searches binary files for tool names, checks file names, and the zip for a comment, and it opens gzip files. The statements it fails, in the wordings the real files use: "generated by ...", "built by app/tools/...", "Written to data/x.json by tools/y.mjs", "Derived from a.geojson by app/tools/b.mjs", "(built from the layers by tools/c.mjs)" (also when the comment wraps onto the next line: the end of a line is read together with the start of the next), "recomputed by build_kit_data.py", "(tools/build-gazetteer.mjs)", "(node tools/x.mjs writes this file)", `generated_by: '...'` in a module, the keys `"generated_by"` / `"generated"` / `"built_by"` / `"generator"` and "do not edit by hand". These rules were made stricter on 2026-11-14 (a read of the real shipped files showed nine lines in wordings the first rules did not see: nothing was loosened to pass). Not failed: a program that ships in the build (a comment that says a manifest "is made by real.mjs" describes the product, not its maker) and a checker or a test cited as the method of a reading (`checked by tests/x.test.mjs`, a "tool path" that is counted for the acceptance review, not failed). The words of the working process that name no tool (`workstream`, `horde`, `shard`, "task brief", "this pass") are counted with every pack and printed as "internalWordsForReview"; they do not fail the audit. Two rules of the packer came from delegated decisions and are reversible: the **publication filter** (DD-STG-01) takes a JSON member that names the program that made the file (`"built_by"`, `"generated_by"`, `"generator"`, `"generated": <date>`) out of the SHIPPED copy of a data file, proved on every pack (the edited file equals the working file minus exactly those members; any other difference stops the pack; a shipped module that reads such a key stops it too), while the working files keep them and the audit still runs on the finished folder; and the audit **opens gzip files** (the roster unit files will be `.jsonl.gz`) and treats a given name printed in the name field of a roster row (the given name Claude is printed in three roster rows of the Vermont and New Hampshire files and once in a flag file) as data (DD-STG-02), never anywhere else. Run on the roster data as they are today: the 118 gzip files have 0 hits; the index file `rosters/data2/INDEX.json` has one (its `about` sentence names the script that built it; request `bt-rosters-staging-copy-audit-index.md`; it is not shipped until the roster section exists, and the self-test "real roster data" is red on it).
