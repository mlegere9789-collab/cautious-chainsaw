(2) `data-src/` starts as a copy (`oob/ tracks/ vignettes/ terrain/ monuments/ casualty/ places/ people/ authorities/ aliases/ sources.yaml`, plus `schemas/ policy/ scripts/ CHANGELOG.md decisions.jsonl`); `dist/data/legacy/` and `dist/data/v2/` are build outputs. #### WP-DATA-02 - Versioning: manifest, `data_version`, `dv`, changelog, stamps (M 1.5-2.5 d, A)
**Why.** No version, hash or changelog; one file name has carried different bytes (D-ORDER); permalinks must survive re-timing (D-URLSTATE).
**Fix.** (1) `data_version` semver: MAJOR = ID removal/rename without alias, schema break, unit or tick semantics; MINOR = new records/fields/sources; PATCH = corrections. Legacy `0.9.0`, first validated release `1.0.0`. (2) `dv` is chapter 04's calibration stamp (links without `dv` mean 1, the first calibrated set is 2, bumped only on an anchor-set change [ch04 4.3, 4.8]); the manifest copies it and this chapter never bumps it: ID merges are absorbed by `unit_aliases.json` (WP-06), retired moment ids by ch04's tombstones and `tick-migrations.json`; position corrections change `data_version` only. (3) `dist/data/data-manifest.json` (no-cache): `{data_version, dv, built_at, schema_version, time_model, files:{logical -> {path, sha256, bytes}}}`; v2 packs are `<logical>.<hash8>.json` with hash = base64url(sha256(bytes))[:8]; committed `data.lock.json` (name -> sha256) fails CI when a name returns with other bytes (Rollup hashes are not recomputable [S app-time-13]). (4) `CHANGELOG.md` (Added/Changed/Corrected/Removed); each Corrected entry `{record_id, before, after, citation, reviewer, date, dv_impact}`; rule D001: any `data-src` hash change needs a changelog line and version bump. (5) Stamps: Help About "Data v1.2.3, 2026-11-05", PDF footer, `window.__GTBG_DATA__`, Report-a-problem prefill, `dv=` in share links, Historian answers; records edited after 1.0.0 carry `updated`/`rev` (30-day "recently corrected" badge). (6) No `location.reload()` on data updates (C6): a toast.
**Acceptance.** `verify-manifest.mjs`; Playwright: a `dv=1` link opens correctly after a seeded bump to 2; D001/D002 fail on a silent edit; About equals manifest. **Risk.** two version numbers confuse: `data_version` = bytes, `dv` = clock.

## Appendix A - Reproducing the numbers
`plan-work/tmp-data-integrity/lib.py` + `oobidx.py` reproduce 2.1-2.2. Segment statistics (2.3): merge rows by (unit,tick), density last; classify consecutive pairs by haversine distance (< 30 / 30-250 / > 250 m); anchors needed = sum of ceil(dt/target)-1 with dt from `time-facts-anchors.csv` (piecewise linear); visible units = first <= t <= last, or inside the hold window.
