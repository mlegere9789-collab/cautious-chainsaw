## 4. Metric-by-metric roadmap

Reading rule: Lantern lab numbers are model outputs; also read the observed (unthrottled) values. Three measured couplings bind the order of work: (a) removing the reload alone lowers lab mobile 64 to 51 (TBT 16 to 492 ms) because bundle evaluation stops hiding before the simulated FCP; (b) deleting the intro alone gives 46; (c) a boot-after-FCP loader with the entrance animations still on leaves observed FCP at 4.3 s. So WP-PERF-05 ships atomically (loader + no reload + no fades + no modulepreload), WP-PERF-07 follows, and neither is reported as a fix alone. TBT will read worse after R0 (27 ms artifact to 160-470 ms) and recovers only with the split in the rebuild; that is not a regression.

### 4.1 FCP (Poor badge; lab mobile 4.10 s, desktop 0.83 s; field bucket median 0.95 s)
- Causes, ranked: (1) the parser-inserted 2.28 MB module runs at end of parse with no rendering opportunity [S perf-cwv-02]; (2) `body{animation}` and the splash fade keep text at opacity 0 so it is not recorded as contentful (FCP 892 vs 4,196 ms in perf-runtime's A/B, 1,259 vs 4,304 ms in perf-cwv's; effect measured twice, mechanism inferred); (3) Lantern counts the 604 KB modulepreload as FCP-critical (lab artefact; real analogue is bandwidth contention); (4) blocking `site-nav` chain (+150-450 ms at 150 ms RTT; Lighthouse shows 0 ms); (5) the reload discards the first page (RUM sees only the fast second page); (6) 27 s outliers unexplained [U].
- Fixes: WP-05, WP-24, WP-18, WP-27. Expected: lab 0.9-1.0 s mobile / 0.26 s desktop (v5/v8/v9/v10 measured 0.91-1.00); field p75 mobile 4G 1.0-1.5 s. Confidence high (mechanism), medium (field).
- Measure: Lighthouse x5; probe filmstrip; beacon FCP with `loadState`/`timeToFirstByte`/`resourceLoadDelay` by device x firstVisit x swControlled x navType. Guardrail: p75 <= 1.2 s (alert 1.44, n>=30), pre-FCP inline JS <= 8 KB, <= 1 render-blocking CSS.

### 4.2 LCP (Poor badge; lab mobile 9.0 s sim / 0.29 s observed; probe 4.78 s mobile, 4.93 s desktop; 33% of hourly p75 > 4 s)
- The element is the story-panel vignette text ("The battle was over...", 108k/145k px2) painted while the intro sweeps 675 ticks; LCP runs until first input, so click-early visitors (median bucket 1.8 s) and intro-waiters (4.6-5 s) make the bimodal series [S perf-cwv 4.2]. A static hero alone cannot fix it: any larger text painted before input takes over (10.1 s live, perf-runtime MISSED-4).
- Causes: (1) intro `tO` (BP:101471-101560); (2) no locked hero: `createRoot` removes `#boot-splash`/`#seo-content` (BP:113365), later panels win; (3) white boot; (4) lab-only reload chain; (5) lab fragility: Lighthouse stopped at 3.1 s on the replica desktop but ran 44.5 s live, so a pass can depend on trace-window luck (WP-01 guard).
- Fixes: WP-07, WP-05, WP-18, WP-01, WP-21 (Turning Points is empty until JS), WP-19/20, WP-27. Expected: probe 604 ms mobile / 448 ms desktop stable for 20 s (v10 measured); lab 0.9-1.0 s / 0.26 s; field p75 <= 1.8 s mobile 4G [E], <= 1.0 s desktop. R0 alone leaves field LCP at 4.6-5 s for intro-waiters: do not claim it. Confidence high.
- Guardrail: p75 <= 2.0 s (internal target 1.5 / 0.8), `elementRenderDelay` <= 700 ms, allow-list element in >= 95% of rows.
