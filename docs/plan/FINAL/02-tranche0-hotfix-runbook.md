## 1. What Tranche 0 is, and its rules

Tranche 0 (T0) is the closed, scripted patch set that makes the CURRENT site stop being broken while the rebuild is prepared (D-SOURCE default: strangler rebuild + closed Tranche 0). It is deleted the day the rebuild serves `/map`. Its ceiling is B/B+ (patch-forever, weighted 1.9 [S prov-recon 6.2]); A+ needs the rebuild.

Rules that bind every WP:
1. **Order (D-ORDER):** archive and baseline (0.0) -> R0 mechanism release (0.1) -> everything else. Nothing that ships bytes precedes R0.
2. **Never reuse a filename for different bytes.** Every changed asset (entry, both lazy chunks, CSS) ships under a new release-id name; a CI-style check compares every published `assets/*` name to `_ops/used-names.txt`.
3. **One runner, asserted anchors.** Each patch is an exact string whose match count is asserted against the current text; the runner pins the input md5 (`7ef75b95f4c02700430b8aa91e3a7459`) and refuses to run on patched input.
4. **Closed list.** Only D-SOURCE item 2 plus the additions named in section 14. Anything else needs an ADR amendment.
5. **No identity changes in T0:** no URL form, title tag, meta description, canonical, sitemap or product-name change (S1/S2 trains, section 4.2 of the register; the one sitemap edit allowed is dropping `ar.html` together with its `noindex`, as D-SCOPE-TIERS "hide now" requires, and that is a content-set change, not a URL-form or `lastmod` change); no `/data/*` file edits (M8: `/data/*` is `max-age=3600` under fixed names, so an in-place fix is stale for an hour and skews against a new immutable bundle [S app-bugs M8]); no clock-label edits (D-TIME).
6. **Deploy discipline:** Tue-Thu only, none in 2026-11-15..20, one production deploy per train, 15 Netlify credits each (plan UNVERIFIED, owner action 5).
7. **Rollback is "Publish deploy" of the previous deploy** (atomic); every train names its rollback and post-deploy probe first (section 8).
