### 4.1 The exact definition of "parity"

- **Reference R** = frozen production bytes: `legacy/dist` from the case-correct source zip (bundle md5 `7ef75b95...`) on the hermetic rig (WP-ARCH-05) with probe patch **P0**, one appended statement exposing `window.__legacyProbe = {yn, y1, i2, iF, zp, Hk, vF, ...}` (module scope holds every minified binding). P0 adds no behaviour: the rig self-test proves R+P0 and R give identical text, console and request logs on 10 checkpoints. T0 bridge builds are R plus registered patches; `/classic/` at cutover is the last bridge build.
- **Candidate N** = the new app at SHA S; test hooks ship as a lazy chunk active only under `?test=1`, so tested bytes equal deployed bytes. **Data snapshot D0** = legacy `/data/*.json` byte-identical; N is built with `--data-snapshot=D0` for the gate so code parity is isolated from data corrections (which ship later under DV validators and their own entries).
- **Observable surface:** T1 unit frames (id, lat, lng, bearing, strength, disposition per tick; trails; filters; loader counts; successions; search); T2 data-bearing text keyed by panel role and heading, control inventory (role + accessible name; legacy glyph labels mapped by `chrome-map.json`), reachability and geometry constraints, state, URL, storage keys; T3 pixels (advisory); NP console, requests, budgets, map count.
- **Parity holds for SHA S** iff on the checkpoint set C(S) >= C_min (4.2) under the determinism rules: (P1) every T1 difference is 0 (tolerance 1e-9 deg; data has <= 4 decimals), the legacy visibility rule being `carry: forever` from forward traversal with a fresh accumulator unless ID-CARRY is signed; (P2) every T2 difference matches an unexpired registry entry whose pinned `next` equals the observed text; (P3) N's console errors and warnings are a subset of R's and N's own gate is 0; (P4) 0 stale, 0 expired entries, every behavioural entry signed and carrying an audit id or `new:` justification; (P5) every P-01..P-62 row is implemented (green checkpoint), replaced (`change`), deleted (D-SOUND, D-HEATMAP: `remove`) or deferred (max 3: Walkthrough, NPS Tour, Soldier's Eye; dated; `/classic/` stays until the last lands); (P6) storage compatible both ways; (P7) canonical and alias URL params parse to the same state and `pageshow.persisted` holds from sub-pages; and P1-P7 hold on 7 consecutive nightlies plus the release commit.
- **Not parity:** data corrections, new features (kind `add`, flagged), Lighthouse/CWV budgets, a11y conformance. **T3 decision** (deviation from prov-recon 6.6, qa-ci 6.2; section 10): SSIM >= 0.98 on chrome is unattainable by design (D-DESIGN tokens, Spectral, SVG icons, one shell); T3 is a generated side-by-side contact sheet reviewed per PR, and gating visual baselines belong to the QA chapter for the new design.

### 4.8 Unit renderer decision protocol (D-UNIT-RENDER) and R1 specification
