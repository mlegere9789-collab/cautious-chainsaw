# Ask the Historian: schemas

Field-level reference for the seven record types (source, document, passage, entity, fact, anchor, answer), the manifest and the validation report. Everything here is what the code in this repository does today (KB version 0.1.0, schema 1); where a shape is reserved for a later phase it says so.

Conventions: ids are strings; `s` and `e` are UTF-16 offsets into the named text (`e` exclusive); "sb" is a list of sentence start offsets; JSON on disk is written with recursively sorted keys and no whitespace so identical content gives identical bytes.

## 1. Source (rights register)

File: `docs/historian/sources.yaml` (generated by `tools/historian/gen-sources.mjs`; read by `tools/historian/lib/sources.mjs`; parsed by the dependency-free `yaml-lite.mjs`, which supports the subset the register uses).

Top level:

| Key | Type | Meaning |
|---|---|---|
| `tiers` | map | text of tiers `A`, `B`, `C`, `A-pending` |
| `tier_rules` | map | `V02` (build gate) and `fetcher` (fetch gate), in words |
| `refused_identifiers` | list | Internet Archive identifiers that are never fetched (the 1971 reprint `warrebellionaco00cowlgoog`) |
| `banned_hosts` | list | 27 hosts that are never contacted (Tier C and link-out-only sites); compared case-insensitively, without trailing dots, including sub-domains and anywhere inside a URL (proxy and web-archive wrappers) |
| `sources` | list | one record per source (85 today: 54 A, 12 B, 14 C, 5 A-pending) |

Source record:

| Field | Type | Notes |
|---|---|---|
| `id` | string | unique (`site-records`, `or27-1`, `nyfr`, `fox-1889`, ...) |
| `title` | string | |
| `xref` | `{hs1, hs2}` | ids in the two source catalogues under `docs/plan/data/` |
| `tier` | `A` `B` `C` `A-pending` | the gate |
| `tier_detail` | string | why, and what is still to be confirmed |
| `license` | `{id, statement_text, statement_url}` | `id` is required (V02) |
| `imprint` | `{year, publisher, reprint, ia_id}` | `reprint: true` fails V02 (original scans only); `ia_id` is the Internet Archive identifier used by the fetcher |
| `author_affiliation` | string | |
| `attribution` | string or null | required for Tier B |
| `may_index`, `may_redistribute`, `may_send_to_llm` | boolean | `may_send_to_llm` is only allowed on Tier A; Tier C is false for all three |
| `genre`, `scope_default` | string | `site_record`, `official_report`, ... / `core` |
| `ocr` | `{engine, proxy, gate}` | `proxy < 0.80` must have `gate: quarantine` (V02) |
| `hosts` | list | hostnames the source lives on (fetch gate) |
| `archive_url` | string or null | |
| `status` | string | `shipped`, `wave-1`, `planned`, ... |

Rules (V02 and the fetch gate): Tier C is never fetched, stored or shipped; a missing licence id, Tier B without attribution, `may_send_to_llm` on a non-A source, a reprint imprint, an unquarantined OCR proxy below 0.80, or an A-pending source that would ship external text, each fail the build. `fetchAllowed(registry, url)` returns `{ok, reason}` before any network call; `createFetcher().gate(url)` additionally requires the archive.org identifier to be registered and Tier A or B.

## 2. Document (ingestion, Official Records volume 27)

Produced by `tools/historian/ingest/or27.mjs` `segmentReports`. One document is one report.

| Field | Type | Notes |
|---|---|---|
| `doc_id` | string | `or27-1:0190` (source id, report number padded to four digits) |
| `no` | integer | the report number as printed, restored from the contents list when the OCR misread it |
| `title` | string | the header line(s) ("Report of Brig. Gen. Charles Griffin, ...") |
| `toc_title` | string or null | the contents-list entry for the same number |
| `author`, `unit` | string | split from the contents entry ("Col. Joshua L. Chamberlain" / "Twentieth Maine Infantry") |
| `start`, `end` | integer | offsets into the normalised volume text |
| `text` | string | the normalised report text |
| `pages` | `{start, end}` | printed page numbers (from the running heads) |
| `confidence` | `A` `B` `C` | A: header agrees with the contents list; B: contents entry present but header differs, or recovered; C: no contents entry |
| `recovered` | null or `toc-author` | set when the number line was unreadable and the report was found by its author near a "Report of" line |

Run report (`historian-src/raw/or27-1/report.json`, git-ignored): `chars_in`, `chars_out`, `edits`, `edit_kinds`, `page_marks`, `page_marks_inferred`, `running_heads_left` (the broad count: whole-line heads and heads or signature marks inside body lines), `toc_entries`, `docs`, `recovered_from_toc`, `docs_with_pages`, `passages`, `table_debris_dropped` (ids of the chunks dropped as OCR'd tables), `confidence`, `missing_detail` (for each report number of the run that is not a document: `{no, reason: header-not-found | no-contents-entry, contents_title, previous_document, text_in_previous_document}`) and `docs_missing_from_run`.

Normalisation is logged: every edit is `{why, from, to}` (`dehyphenate`, `hyphen-kept`, `ocr-dict`, `ufffd-dash`, `ufffd-drop`); the run report counts them. Nothing here is committed: raw and normalised texts live under the git-ignored `historian-src/raw/` and `tmp/historian-cache/`.

## 3. Passage

Two related shapes share the passage idea: the **shipped** passage (tier T2, from the site's own records) and the **ingested** passage (Official Records chunks; not shipped in H0 to H2).

### 3.1 Shipped passage (`f/tx/NNNN.<hash>.json`, 16 per shard)

Shard: `{h: [field names], p: [[...row...], ...]}`. Fields, in order:

| Field | Type | Meaning |
|---|---|---|
| `num` | integer | dense passage number (shard = `floor(num / 16)`) |
| `id` | string | `<doc>#<8 hex of sha1(text)>`, e.g. `site-bundle-prose:walkthrough-1#4990c8b1` |
| `doc` | string | document id, e.g. `site-records:V-009` |
| `rec` | string | the entity record this passage belongs to (`V-009`, `D2T268`, `WT:1`, `SUCC:US-001`, `U-20ME`) |
| `kind` | string | `narrative`, `chronicle`, `commentary`, `succession_note`, `casualty_note`, `walkthrough`, `tour`, `position_note` |
| `day` | 1, 2, 3 or null | |
| `text` | string | the passage, cleaned (no developer notes, no ids) |
| `sb` | integer[] | sentence start offsets |
| `cite` | `{author_line, short}` | the citation the reader sees (`short`: "Site vignette “Vincent and Little Round Top”, paragraph 6 of 10") |
| `ents` | `[[entityId, role, weight], ...]` | entity links; role 2 subject/author, 1 mention |
| `clk` | integer[] | start offsets of the sentences that contain a clock string (58 passages have one). Informational: the runtime quotes such a sentence as the site's own wording and never derives a clock from a tick |
| `source` | string | source id (`site-records`, `site-bundle-prose`) |
| `prior` | number | kind prior used at ranking time |
| `sens` | 0 or 1 | sensitivity flag (reserved; 0 for all H0 to H2 content) |

Counts (current build): 1,530 passages, 26,869 words: narrative 249, chronicle 137, commentary 25, succession_note 42, casualty_note 3, walkthrough 48, tour 48, position_note 978.

Postings (`f/ix/NNN.<hash>.json`, 128 buckets by `fnv1a32(stem) % 128`): `{b, t: {stem: [num0, q0, dnum1, q1, ...]}}`, doc numbers delta-coded, `q` an impact in 0..255 (`impact = q / 255 * lexicon.scale`). Entity postings (`f/en/NN.<hash>.json`, 32 buckets by `fnv1a32(entity id) % 32`): `{b, e: {entityId: [num0, role0, dnum1, role1, ...]}}`. The wire format lives in `historian-src/core/codec.js` and is used by both the build and the runtime.

### 3.2 Ingested passage (Official Records, scaffold)

Produced by `chunkDocument`:

| Field | Type | Notes |
|---|---|---|
| `id` | string | `or27-1:0190#<8 hex>` |
| `doc_id` | string | |
| `seq` | integer | position within the document |
| `text` | string | paragraphs joined by a blank line; normalised whitespace |
| `sb` | integer[] | sentence starts inside `text`, from the sentence splitter (with 1863 abbreviations: Hdqrs., Genl., Sergt., Comdg., Asst., Adjt., Lieut., Col., Fred., Chas., "p. 179", "Aug. 12", stray OCR dots) |
| `words` | integer | |
| `s`, `e` | integer | offsets of the passage inside the document text (so a passage can be traced to the printed page and line region) |
| `pages` | `{start, end}` | printed pages |

A chunk that is an OCR'd table (20 or more paragraphs, at least half of them four characters or fewer) is not a passage: it is dropped and its id is listed in `table_debris_dropped`. Running heads and sheet signatures, whether on a line of their own or inside a body line, are removed before chunking. Sample result: 1,513 chunks, 48 dropped, 1,465 passages.

Bounds: aim for 150 to 250 words, paragraph aligned; a paragraph longer than 250 words is cut at sentence boundaries (at a word boundary inside an over-long sentence); a short tail (under 60 words) is merged into the previous passage, so a passage never exceeds 310 words. Passages never cross documents.

## 4. Entity (tier T1, `f/entity.<hash>.json`)

File: `{schema, kb, common, nameTerms, unitKeys, records}`.

| Key | Meaning |
|---|---|
| `records` | 1,694 entity records (below) |
| `unitKeys` | map from a derived unit key (ordinal token, then state: `#1|minnesota`, `#102|new york`) to record indexes, for the unit-grammar linker |
| `nameTerms` | stems of every name token: the vocabulary typo repair searches |
| `common` | surnames that are also ordinary English words (capitalisation guard) |

Record (common fields):

| Field | Type | Notes |
|---|---|---|
| `id` | string | the site's own id where one exists, so batteries and golden ids resolve |
| `k` | string | kind: `regiment` 466, `person` 706, `chronology` 137, `artillery` 103, `brigade` 88, `division` 31, `artillery-unit` 23, `succession` 42, `terrain` 30, `vignette` 24, `corps` 11, `monument` 9, `road` 8, `structure` 8, `feature` 4, `army` 2, `casualty-note` 1, `site` 1 |
| `label` | string | short display label ("20th Maine") |
| `title` | string | longer form ("20th Maine Volunteer Infantry") |
| `aliases` | string[] | derived and curated aliases (`1st Minnesota`, `First Minnesota`, `1 MN`, `Colonel Chamberlain`) |
| `par` | string[] | ancestors for units (`["BDE:U-V-1-3", "DIV:U-V-1", "CORPS:U-V"]`) |
| `side` | `U` `C` | |
| `attrs` | object | kind-specific facts; the only source of numbers in answers |

Id namespaces: site ids `U-20ME`, `C-15AL`, `LOC-006`, `V-012`, `D3T538`; derived `BDE:U-I-1-1`, `DIV:C-I-3`, `CORPS:U-I`, `ARMY:U`, `ART:U-ART-A4US`, `SUCC:US-001`, `ROAD:RD-004`, `STR:STR-001`, `TF:TF-002`, `CAS:...`, `SITE:find-ancestor`; new `P:<slug>` (person), `WT:<n>` and `TOUR:<n>` (prose stops).

Regiment `attrs`: `strength`, `casualties`, `pct`, `pctDerived`, `estCas`, `days`, `ka` (the site's key-action text), `cmd {name, rank, fate}`. Brigade and division `attrs`: `strength`, `casualties`, `pct`, `days`, `states`, `ka`, `nick`, `cmd {name, rank, fate, succ: [{name, rank, when}]}`. Person `attrs`: `name`, `given`, `surname`, `rank`, `fate`, `general`, `prom` (army 4, corps 3, division 2, brigade 1, else 0), `roles: [{u, l, r, w}]`. Chronology `attrs`: `day`, `tick`, `location`, `sig` (`critical`, ...), `text`, `units`. Succession `attrs`: `from`, `fromRank`, `to`, `toRank`, `unit`, `cause`, `when`, `notes`, `source`. The chronology `time` label and every developer field are never carried.

`f/entix.<hash>.json`: the card BM25F index `{N, avgLen, len: {id: length}, post: {term: [...]}}` over label, aliases, title and attribute text with field boosts.

## 5. Fact tables (`f/facts.<hash>.json`)

Every number a composer prints comes from an entity attribute or a row here (I2).

| Key | Shape |
|---|---|
| `rank` | `{ "regiment.rate.U": {rule, rows: [[id, percent, casualties, strength], ...]}, "regiment.losses.C": ..., "artillery.size.A": ..., ... }`; `rule` is the sentence that qualifies the ranking ("regiment records with strength of at least 100; records showing zero casualties excluded") and is printed with the answer |
| `rollup` | `bySide`, `byState` (`"U|Maine": {n, ids, strength, casualties}`), `echelons` (brigade to regiment ids), `guns` (`{U: {batteries, guns, casualties}, C: ...}`), `armyVsCorps` (reconciliation of army-level and corps-level figures) |
| `succ` | `byUnit` (`"CORPS:U-I": ["SUCC:US-001", ...]`), `byPerson` |
| `events` | `byDay` (chronology ids in order), `critical` (the critical events per day) |
| `scope` | ordered scope rules `{id, mode, pointer, re: [...], text}` (medical, finance, creative, code, visit, weather, adjacent, causes, injection) |
| `unknowns` | questions the records cannot answer: `{id, re, text, answer_with, needs_place?, standalone?, evidence?}`. `text` is the honest limitation; `answer_with` is the words for "what would answer it" (every entry has one); `standalone: true` makes the engine answer the question from this entry even when no record is linked (weather at the battle, the Gettysburg Address); `evidence` says which of the site's own passages may be quoted under the limitation (for weather, only sentences that really remark on the weather, and only for the asked day). Today: `per-location-casualties`, `individual-soldier`, `weather-at-battle`, `gettysburg-address`. |
| `clock` | the baked time model: `{model: {version, release, dv, tz, sha256, anchors, signed}, solar: {dawn, sunrise, noon, sunset, dusk, nautical}, ev: {chronologyId: [minutesAfterMidnight, sigmaMinutes, flags, rangeText?]}}` (137 events). `minutes` is the model's clock for the event on its own day, `sigma` its uncertainty, `flags` is a bit set (1 = approximate, 2 = contested) and `rangeText` the accepted range at an anchor ("between about 5:00 and 5:30 AM"). Built by `tools/historian/lib/clock.mjs` from the time model; used only by `core/clock.js` and `core/atime.js`. Absent on a build made without the time model, in which case clock questions are not recognised as such. |
| `routes` | pointers to site pages (`/find-ancestor.html`, ...) with why |
| `domain` | domain vocabulary that anchors a question to the battle |
| `outcome` | `{text, basis, records, auth, reviewed}`: the outcome statement, the records it rests on and the sentence that says so |
| `glossary` | `{echelons: {text, basis, reviewed}}`: the plain definition of regiment, brigade, division, corps |
| `authority` | per side, the army-level and corps-level strength and casualty figures the roll-ups are reconciled against |
| `battle` | `{name, dates}` |
| `premises` | false-premise checks (`{id, kind, note}`), e.g. asking how a commander who survived "died" |
| `intents` | reserved (null in this build) |

Lexicon (`f/lexicon.<hash>.json`): `{schema, N, avgLen, k1, b, buckets, scale, terms, df}`; `terms[i]` has document frequency `df[i]`; BM25 parameters `k1 = 1.2`, `b = 0.75`.

## 6. Anchor (reserved, H3 and later)

An anchor ties a quoted span to its printed source: `{passage, doc, folio or page, line range, char range, image}` so a quote can link to the page image. **None are produced at H0 to H2** (validators V07 anchors and V08 folio sample are no-ops in this build). The ingestion scaffold already records what an anchor needs: printed page numbers per document and passage, and character offsets of each passage inside its document.

## 7. Answer (runtime output of `engine.ask(question, ctx)`)

```
{
  kb: "0.1.0", query, mode: "answer" | "partial" | "decline" | "clarify", route: "records" | "ancestor" | ..., intent,   // intent includes "at-time" for a clock-of-day question
  decline_reason?: string,                    // present on decline / clarify
  entities: [{id, label, kind, w}],           // what the linker found (labels are for display)
  did_you_mean: [{from, to}] | null,          // typo, join and split repairs; `to` is always a whole word of the question or of the name vocabulary, never a stem
  blocks: [Block],
  chips: { follow: [{label, q}] },            // every q is answerable (tested)
  links: { pages: [...] },
  shown: [id],                                // records the answer is about, in order (used by the metrics)
  sources: [{id, label, kind, href}],         // href only for regiments and site pages, and only same-site
  cites: [id],                                // every record id the answer relies on
  ranked: [id], limited: boolean, injection_stripped: boolean,
  text: string,                               // plain text of the blocks (evaluation, clipboard); contains no ids
  trace: {intent, notes, unknown, mentions, ranked, ms, ...},
  ctx: { lastEntities, lastIntent, lastSide, shownPassages },   // pass back on the next call
  lint?: [{rule, msg, ctx}]                   // present only when a defect was found (never shown by the page)
}
```

Blocks:

| `t` | Fields |
|---|---|
| `lead` | `runs: [{txt, ent?}]`, `src: [id]` (a run with `ent` is an entity mention; the page links it when `sources` gives a same-site href) |
| `note` | `code` (`authority`, `debate`, `injection`, `rank-rule`, `basis`, ...), `txt` |
| `quote` | `passage`, `rec`, `s`, `e`, `text`, `kind`, `clk`, `attrib`, `cite`, `source` (invariant I3: `normalise_ws(passage.text.slice(s, e)) == text`) |
| `list` | `title`, `items: [{txt, ent?}]`, `more?`, `src: [id]` |
| `table` | `kind` (`compare`, `compare-places`), `caption`, `cols`, `rows`, `src`, `note?` |
| `chips` | `items: [{label, q}]` |

Context passed in: `ctx` from the previous answer, plus optionally `onsite: {selected_unit, tick, day, location}` from the map. `ask` never throws on a malformed context: `cleanCtx` keeps only what it can use (a non-object becomes empty; `lastEntities` and `shownPassages` keep only strings of at most 80 characters, the last 6 and 40; `lastIntent` and `lastSide` only as strings and `U` or `C`; `onsite` only a string `selected_unit` and `location`, a finite `tick` and a `day` of 1, 2 or 3) and the question is answered with what remains. Error handling: a shard that cannot be fetched raises `ShardError` (`retryable: true`) out of `ask`; the caller shows "Try again" and asks again.

## 8. Manifest (`hx/manifest.json`, the only mutable file)

`{schema, kb_version, kb_hash, counts {entities, passages, terms, units, words}, data_snapshot {dir, files, sha256}, sources [{id, tier, license, passages}], tiers {entity, entix, facts, lexicon: {path, bytes, sha}; index: {buckets, files, hash, codec, scale}; entpost: {buckets, files, hash}; text: {files, per_shard, fields}}, bundle_prose {file, walkthrough, tours}, semantic {enabled: false}, ai {enabled: false}, redactions, eval, time_model {version, sha256, dv, tz, anchors, release: "candidate", signed: false}}`. `time_model` says which version of the time model the baked `facts.clock` came from and that it is a candidate that has not been signed off. `data_snapshot.sha256` is a hash of the 71 data files the build read; the evaluation and the regression guard record it so a data change is noticed.

## 9. Validation report (`historian-src/dist/validation-report.json`)

`{kb_version, data_snapshot, ok, counts, findings, sizes {t1Raw, t1Brotli, perFile, maxShard, ixTotal, textTotal, maxIx}, stats, warnings, curated_unmatched, entities {kind: n}, passages {total, byKind, words, withClockClaim}}`. K001 findings name the collection and the field (`regiments.strength is no longer loaded (recorded populated in 467/467)`, `regiments.men is a new whitelisted field with no recorded coverage`, `regiments.casualties is populated in 40/467 records (9%), recorded 467/467 (100%): the source field was renamed, dropped or emptied`). `findings` is empty on a passing build; each finding is `{rule, level, msg}`. The build exits non-zero on any error-level finding.
