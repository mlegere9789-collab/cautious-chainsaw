## What is OPT-IN (train R1c, when asked for) and what does not ship

```
python tools/t0/build.py --train R1c --with PG-legal      # the one command that includes the legal text (a train before R1c says "not part of train" and adds nothing)
```

## Regenerate and check

```
python ops/legal-drafts/build_pg_legal.py                       # rewrite PG-legal.json, previews, OWNER-SIGNOFF.md, data-inventory.md
python tools/t0/build.py --train R1c --with PG-legal --out tmp/<you>/build      # the patches apply with 0 anchor failures; the gate check no-owner-notes passes
node ops/legal-drafts/verify-facts.mjs --dist tmp/<you>/build/dist             # "no FAIL" (the dates, the Street View sensor sentence against the headers, the referrer sentence ...)
node ops/legal-drafts/verify-facts.mjs --dist legacy/dist       # RED on the current site: 31 FAIL on 2026-09-30 (the live privacy page misses every item)
python ops/release-fixes.selftest.py --only 7                   # opt-in, pinned date, no marker, bad pin / stray placeholder / leftover marker are errors
```

A tree built by the build system WITHOUT the legal group keeps the baseline privacy/terms pages: `verify-facts.mjs` then prints `INFO legal-opt-in` and skips the policy-coverage checks (they would only describe the old page), but still runs the host, storage, cookie, permission, marker, Terms-embed, frame-permission and referrer checks. A tree without `version.json` (`legacy/dist`, `baseline/dist`) runs all checks.

`verify-facts.mjs` fails a tree that: references a host not in the inventory; uses a storage key or cache name not in the inventory; writes `document.cookie`; uses camera/location/orientation APIs outside `ar.html`; has an on-device page (`ar`, `historian`, `cinematic-export`, `immersive`) that fetches anything but same-origin `/data/*` or uses a beacon/socket/XHR; has a `privacy.html` that does not name every inventoried host, key, cache and permission; contains an owner-review marker ANYWHERE in a shipped text file (visible or in a comment) or a hard-coded "September 30, 2026"; in a legal-group tree, dates that differ from the pinned `trains.json` `legal.effective_date`; delegates a device feature to a third-party frame (iframe `allow` attribute / Permissions-Policy naming another origin) without the privacy text saying so, or says so without the bundle and `_headers` backing it; says the referrer is only this site's address while `_headers` sends another `Referrer-Policy`; or (coupling checks) says PeerJS is fetched only on Host/Join while `watch-together.html` still loads it at page load. It fails when the Terms embed sentence is not backed by the generated `_headers` (`/embed` and `/embed.html` freed). Negative test 2026-09-30 (first pass): seeding a tracker host, a new key, a cookie write, a missing "compass", a visible marker and a static PeerJS tag into a copy of the R1c tree gave 7 FAIL; second pass: a header delegation without the privacy sentence, and a leftover owner marker, each FAIL.

## Owner sign-off list (what must be read or confirmed before a build with `--with PG-legal` is deployed)

The full list is generated into **`OWNER-SIGNOFF.md`** (and repeated in the `note` of the patch it belongs to). It used to be `[OWNER TO CONFIRM]` HTML comments inside the page source; nothing of it is in the shipped bytes any more (`tools/t0/gate.mjs` check `no-owner-notes` and `verify-facts.mjs` fail a build that still contains one). In short:

1. **Dates.** `privacy.html` "Last updated" and `terms.html` "Effective date" (and the first entry of the privacy change log) are the placeholder `{{LEGAL_DATE}}`; the build prints the pinned `legal.effective_date` of `tools/t0/trains.json` as "Month D, YYYY" (today `2026-11-03`, the planned R1c deploy day). **Set it to the real deploy day before the build you deploy.** The text itself was checked against the code on 2026-09-30 (`data-inventory.json` `verified_on`); an invalid pin is a build error.
2. Netlify Web Analytics: the second sentence of the "Hosting and traffic statistics" item says Netlify's server-side analytics reports page views, unique visitors by IP address, referrers, countries and pages not found. The owner's PDFs imply it is on; unverifiable from outside (register question O-12). If it is off, delete that sentence.
3. Netlify Real User Monitoring stays on (it is on today: Netlify injects the script into 27 of 27 live pages). If it is switched off, delete that item.
4. Street View motion sensors: the privacy text says the site lets the Street View frame (and no other outside frame) read the device's motion sensors. That is true only for R1c with the bundle patch `CP+walkthrough-sensors.json` and the generated Permissions-Policy (`ops/header-decisions.md` section 2); the generator grants the header only when this sentence is in `privacy.html`. Check it on a real phone; if you would rather not share motion sensors with Google, drop the patch and `PP_APP` and delete the sentence.
5. Terms: the sentence about embedding "its widget" is **not edited**. It is true because the generated headers free `/embed` and `/embed.html`; `verify-facts.mjs` checks the built `_headers`.
6. Terms: "the written vignette scripts are the creator's own work" (live, unchanged) cannot be confirmed from the repository (four data notes cite a "Gettysburg Animated YouTube vignette", register action 10a). Left as is; flagged.
7. Contact stays the Gmail address on purpose (role addresses do not exist yet: `contact-architecture.md`).

## Differences between the merged drafts and infra-netlify Appendix H (why they are not a copy)

* Referer: Appendix H says third parties receive "the address of the page you are on"; the site sends its origin only (`Referrer-Policy: strict-origin-when-cross-origin`).
* Street View is not click-to-load today (the frame opens with the Walkthrough); the click-to-load wording is bracketed `[[WHEN SHIPPED]]`. The NPS frame already is on-demand, so its bracket is removed.
* Cache Storage: after R0 only same-origin `/assets/*` files, not "data and pages"; plus the `mapbox-tiles` cache; plus sessionStorage keys `gtbg_layout` (R1b), `gtbg_chunk_reload`, `gtbg_boot_retry` (R0), missing from Appendix H.
* "PeerJS's public broker reports an EU location" was not verified and is dropped; PeerJS publishes no privacy policy we could find.
* `security.txt` and role addresses do not exist yet: bracketed.
* Under-13 / under-16 wording removed (register D-LEGAL); the CC BY-NC/BY licence recommendation replaced by the D-LICENSE default; warranty, liability and governing-law text is left for counsel (WP-CONTENT-24).
* Voice: the drafts keep "we" (Appendix H and the live pages); WP-CONTENT-24 (R2) is the neutral-voice pass.
