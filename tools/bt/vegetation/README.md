# Vegetation of July 1863: the build (requirement R20, gate Q21)

Makes `docs/battle-theatre/app/data/vegetation.json` and the register proposals `GOVERNANCE/horde/ws-world/proposed-register/ws-world-veg-G01..G15.md`. Notes for readers of the result: `docs/battle-theatre/app/docs/VEGETATION-NOTES.md`.

## Order

1. `python -I tools/bt/vegetation/verify_claims.py` looks every quote of the claim files up again in the saved text of its source (Official Records, the National Park Service reports, the public-domain library, one saved page) and writes `claims_verified.json`. A generated claim whose quote is not found is dropped and listed; a hand-written claim whose quote is not found makes the run exit 1. Nothing is cited that this step did not find.
2. `python -I tools/bt/vegetation/build_vegetation.py` builds the units (the land-cover layer of the 1863 base map, the open ground cut into field cells), attaches the claims by rule, draws the crop of every cell from the district mix, writes the data and the register proposals. It is deterministic: `--check` compares a fresh build with the committed file and exits 1 when they differ. `--no-register` leaves the proposals alone.
3. `node --test docs/battle-theatre/app/tests/vegetation.test.mjs` (24 tests: the data, the pure state function, the meshes, the plan of the troops' walk, the module with a stand-in theatre and a recording GL context).
4. The browser harness `docs/battle-theatre/app/tests/vegetation-browser.mjs` goes through the machine lock (`tools/horde/bench.sh`); software GL only.

## Files

| File | What |
|---|---|
| `srcs.py` | search and verify across the source families (`OR27`, `NPS:<id>`, `WS9:<id>`, `WEB:<id>`); a quote is matched on letters and digits only, and its place (printed page, PDF page, character offset with the sha256 of the text) is recorded |
| `claims_*.json` | the claims: id, source, quote, tier (`documented` or `inferred`), kind, what it says, what it is about |
| `gen_nps_claims.py` | selects claims from the extract sheets of the web task into `claims_nps_extracts.json` (the snapshot is kept, not regenerated by the build) |
| `veg_tables.py` | the calendars (crop keyframes as ranges, harvest ranges, leaf cover, orchard fruit, the epilogue), the species, the woodlot classes, the three scenarios, the fifteen gaps |
| `build_vegetation.py` | the build; the cut of a block of open ground into field cells is `split_cells` (straight cuts across the long axis of each piece, placed by a seed: not a reading of any map) |
| `or_scan.py`, `warren_px.py` | scratch readers kept for repeat runs (a scan of the Official Records, the pixel size of the Warren sheets) |

## Rules the build keeps

* A crop is `documented` only for a field a claim names and can place; every other cell is a seeded draw from the district mix and says so (`plausible-procedural`).
* Every colour, height, date and share in the calendars is a range with a tier and a reason; the pure state function takes a place inside the range from the unit's own seeded offsets.
* Source titles come from the index of the web task, the library index or the page's own heading; the build adds no author that those do not give.
* Nothing in the shipped data speaks of how it was made (the copy audit words are checked by the node test).
