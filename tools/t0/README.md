# tools/t0 - the Tranche-0 release build system

Turns the locked baseline **`baseline/dist`** (production as of 2026-09-30, reconstructed at source level; entry `assets/index-Cg8FAMXN.js`, md5
`7ef75b95f4c02700430b8aa91e3a7459`) into the four cumulative release trains of chapter 02 (`docs/plan/FINAL/02-tranche0-hotfix-runbook.md`)
**without ever touching `legacy/`**. `legacy/dist` is the downloaded Netlify deploy 6aa16d61; production moved on (`index.html` and
`data/terrain.json` changed in a later deploy, `docs/baseline-drift.md`), so the build starts from `baseline/dist`, which equals `legacy/dist` except
for those two files, and refuses to run when it differs from its lock. Output goes to `release/<train>/` (git-ignored). Everything is deterministic: two builds give the same bytes.

```
python tools/t0/build.py --train R0|R1a|R1b|R1c [--out release/<train>]     # one train (default R0)
python tools/t0/build.py --all                                             # R0, R1a, R1b, R1c
python tools/t0/baseline.py verify-live                                    # RUN BEFORE EVERY DEPLOY: is production still baseline/dist?  IDENTICAL (0) / DRIFTED (1) / could not run (2)
python tools/t0/baseline.py verify | prove | lock | mirror | reconstruct | compare-legacy     # the baseline tooling (section "The baseline")
python tools/t0/tests/baseline_selftest.py                                 # 16 cases: model, lock, build refusal, CRLF, overlay guard, verify-live against a local Netlify fake
node   tools/t0/tests/baseline-drift.spec.mjs                              # T0-BL-01..09: what the live drift does, and that every train keeps it (or supersedes it on purpose)
node   tools/t0/gate.mjs --train R1a                                       # re-run the gates on an existing build
python tools/t0/overlap.py                                                 # geometric overlap audit of the patch set
python tools/t0/ledger.py seed|check|record                                # used-names ledger (ops/used-names.txt)
node   tools/t0/serve.mjs release/R0/dist 8300                             # Netlify-like static server (npm run serve)
python tests/t0/build_selftest.py                                          # 10 properties of the build system (npm run t0:test:build)
python ops/release-fixes.selftest.py                                       # 10 cases: failed builds leave nothing deployable, ledger errors, gate cache beside --out, kill switch outside dist, opt-in legal group, stage guard, verify-url exit codes, stale-dist refusal (staging-verify S0)
node   ops/staging-verify.mjs --train R1c --staging-url <url>              # the staging checklist as a script (S0-S11); --checklist prints it, --local rehearses it against emulators
node   tests/t0/lib_selftest.mjs                                            # the browser harness proves itself (npm run t0:test:lib)
node   tests/t0/r0.mjs                                                     # R0 acceptance in real Chrome (npm run t0:test:r0)
node   tools/t0/verify_release.mjs                                         # independent check of the four built trains: manifest, static crawl, names, identity, cumulative (npm run t0:verify)
node   tools/t0/run_suites.mjs                                             # EVERY suite + red-first proofs against legacy/dist, one summary JSON (npm run t0:test:all; about 65 min)
```
npm: `t0:build`, `t0:build:all`, `t0:gate`, `t0:overlap`, `t0:ledger:seed`, `t0:verify`, `t0:test:build`, `t0:test:lib`, `t0:test:r0`, `t0:test` (those three), `t0:test:all` (the runner), `serve`.
The per-suite commands (journeys, deeplinks, mobile, a11y, copy, pages-core, pages-maps, headers) are in `tests/README.md`; `run_suites.mjs --list` prints the suite table with the exact arguments.
Release notes: `release/<train>/RELEASE-NOTES.md` (git-ignored with the build) are generated by `python tools/t0/release_notes.py`; committed copies live in `ops/release-notes/`; the change log of the tooling itself is `tools/t0/CHANGELOG.md`.
Exit codes of `build.py`: 0 ok, 2 precondition / anchor / overlay / ledger failure (nothing shipped), 3 gate failure (dist kept for inspection). A failure after the build started writing never leaves a deployable-looking `release/<train>/dist`: exit 2 removes `dist`, `manifest.json` and `gate.json` (also those of an earlier good build in the same folder) and leaves `anchors.json` (anchor failures) plus `BUILD-FAILED.json`; `--keep-failed` keeps the partial tree as `dist.failed`; exit 3 keeps the dist next to a `BUILD-FAILED.json` marker. A malformed `ops/used-names.txt` line is a clear error naming the line, checked before anything is written. `ops/sha-list.mjs stage` refuses the dist of a failed build.

## Trains (`trains.json`)

Trains are cumulative. Bundle groups always apply in the fixed order **R0, A, B, DL, C, AX, CP** (AX must follow C; the rest commute, see below).

| train | adds | overlay dirs | config hook |
|---|---|---|---|
| R0 | mechanism (hashed names, boot loader, no-reload SW, version.json) + group R0 (`R0-intro-delete`) and its extension part `R0+mapbox-precompile.json` (`R0-mapbox-precompile`: the app's Mapbox shader programs are requested before their first draw, runbook 14.21); the kill switch is NOT part of the dist (a copy sits beside it, `release/<train>/_ops/sw-kill.js`) | `R0` | no |
| R1a | + group A (crash/input/storage, D-SOUND, D-HEATMAP, AMD-T0-1 error boundary) + page groups `PG-core` and `PG-maps` + assets overlay | `R0 common R1a` | no |
| R1b | + group C (the mobile shell, `C:live-hide-legacy-bar-superseded` in `C+baseline.json`) + group AX (a11y bridge) | `... R1b` | no |
| R1c | + group B (clock/data) + DL (deep links, Turning Points anchors) + CP (copy; extension part `CP+walkthrough-sensors.json`: the Street View iframe `allow` attribute) + `data/moments.json` + generated headers/redirects. The interim privacy/terms group `PG-legal` is **opt-in**: `python tools/t0/build.py --train R1c --with PG-legal` | `... R1c` | `config/gen.mjs` |

The AMD-T0-1 error boundary (formerly the optional group EB) is part of group A (patch `A-error-boundary`), so no bundle group is optional; the only optional group is the page group `PG-legal` (`"optional": true`), included with `--with PG-legal` (see "Plugin interface").
Counts move whenever a group changes, so they are not quoted: read them from `release/<train>/anchors.json` (`summary.patches`; 22 of the records are the R0 mechanism `R0M:*` rows) and `manifest.json` (`file_count`). R0 is stable: 24 anchor records and 121 files (baseline 119; the kill switch used to make it 122).
Ordered dependencies (registered in `trains.json` `known_overlaps`, reported as "known" by `overlap.py`): AX and CP anchor on text that group C produces (AX must follow C, CP must follow C); `bug:K-skip-tour` (A) and `AX-onboarding-dialog` share the prefix `V.jsx("div",{style:tr.overlay`, which A's replacement keeps, so either order matches.

## Build order

1. **Input checks** - the used-names ledger is well-formed (a bad line is a clear error before anything is written), `baseline/dist` against `tools/t0/baseline.lock.json` (per-file sha256 and tree digest of the 119 files; any changed, missing or extra file stops the build and is named), `legacy/dist` tree sha256 (must still be the pinned download), every pinned asset sha256, entry md5, and *no* `/*t0:` sentinel anywhere (refuses to patch its own output).
2. **Bundle groups** - every patch whose `target` is `js` (entry bundle), `help` (HelpModal chunk), `book` (BookmarkPanel chunk) or `css` (app stylesheet), in fixed group order. Each patch's `find` is counted against the CURRENT text and must equal `expect`; failures are all collected, listed with their ids and the build stops (only `anchors.json` is written).
3. **R0 rename / mechanism** (`t0build/mechanism.py`, templates in `mechanism/`) - release id `rid = sha256(entry' 0x00 help' 0x00 book')[:8]` over the patched texts with the three cross-references replaced by placeholders (B.7); writes `index-<rid>.js`, `HelpModal-<rid>.js`, `BookmarkPanel-<rid>.js`, `index-<sha256(css)[:8]>.css`, stamps `/*t0:<rid>*/` on the entry, deletes the five legacy assets (entry, both chunks, CSS, orphan `InterpolationWorker-*.js`), rewrites `index.html` (no `modulepreload`, plain stylesheet, only `preconnect https://api.mapbox.com`, `color-scheme` meta, splash fade removed, idle SW registration + chunk-error guard, `site-nav.js` deferred, boot-after-first-paint loader with one reload retry then a visible "Try again"), removes the body entrance animation from `site-nav.css`, writes the new `sw.js`. The kill switch `ops/sw-kill.js` is NOT copied into dist (the release verifier found it served publicly at `/_ops/sw-kill.js`); `build.py` writes an identical copy to `release/<train>/_ops/sw-kill.js`, outside the dist.
4. **Page phase** - patches with a path `target` (`dashboard.html`, `site-nav.js`, `index.html` ...) from the fixed groups (e.g. C's three `index.html` rows), then the page groups `PG-*.json` (sorted), each with optional `delete` lists.
5. **Overlay** - `overlay/<dir>/**` for the train's dirs, copied over dist (paths relative to the dist root).
6. **Config hook** (R1c) - `node tools/t0/config/gen.mjs <dist> '<json>'`.
7. **Finalize** - `version.json`, `_ops/asset-manifest.json`, `_ops/used-names.txt`; ledger check; the kill-switch copy beside the dist (`<out>/_ops/sw-kill.js`).
8. **Gates** (`gate.mjs`) -> `release/<train>/gate.json`; then `release/<train>/manifest.json` (every file's bytes+sha256, tree hash).

Output layout: `release/<train>/dist/` (deploy this), `anchors.json`, `gate.json`, `manifest.json` (every file's bytes+sha256, tree hash, the `baseline` tree it was built from and `kill_switch`), `_ops/sw-kill.js` (outside dist, never deployed), `.cache/` (gate analysis cache; a default build shares `release/.cache`, a build with `--out` keeps it beside the output), and after a failure `BUILD-FAILED.json`. Nothing in `dist` is timestamped; `version.json` = `{release, train, entry, help, bookmark, css, groups, source_entry_md5}`.

## Plugin interface (other agents add files, they do not edit the build code)

### Patch data files: `tools/t0/patches/<GROUP>.json`
```json
{ "group": "A",
  "patches": [ { "id": "unique-across-all-files", "target": "js", "find": "exact text", "repl": "replacement",
                 "expect": 1, "regex": false, "note": "optional" } ],
  "delete": ["diagnostics.html"] }
```
* `target`: `js` | `help` | `book` | `css` (bundle files, applied **before** the rename, so the release id covers them) or a relative posix path inside dist (`dashboard.html`, `site-nav.js`, `data/x.json` ...). Not allowed: `sw.js`, `version.json`, `_ops/**`, `assets/**` (generated; use the templates in `mechanism/`, the overlay, or a bundle target).
* `expect` (>= 1) is asserted against the current text before the patch applies. `regex: true` uses Python `re` for `find` and `re.Match.expand` (`\1`, `\g<name>`) for `repl`; the count is `len(findall)`.
* Path-target patches may use `{{RID}} {{ENTRY}} {{HELP}} {{BOOK}} {{CSS}} {{TRAIN}}` in `repl` (e.g. `?v={{RID}}` on `site-nav.*` links). Bundle patches may not (no rid yet).
* `delete` removes files from dist after that group's patches (each must exist).
* Unknown keys, duplicate ids, a `group` that does not match the file name, a bundle target in a `PG-*` file: the build fails at load time with the file and patch id.
* **Fixed-order groups** are the ones named in `trains.json` (`R0 A B DL C AX CP`). Add more patches to one without touching the main file with an **extension part** `A+<anything>.json` (`"group": "A"`), applied after the main file's patches, in filename order. New logical groups need a `trains.json` entry (owner of this file: t0-core).
* **Page groups** `PG-<name>.json`: path targets only, applied after all bundle groups' page-phase patches, sorted by file name; optional top-level `"train": "R1a"|"R1b"|"R1c"` = first train that includes it (default `R1a`, so R0 never contains page groups); optional top-level `"optional": true` = in NO train unless the build is given `--with PG-<name>` (today `PG-legal`; `--with` of a group that starts at a later train prints a note and adds nothing; an unknown name is an error).
* **Placeholder `{{LEGAL_DATE}}`** (page-phase `repl` only, for the opt-in legal group): "Month D, YYYY" derived from the pinned ISO date `trains.json` `legal.effective_date` (no wall clock, builds stay deterministic); using it without a legal date is a build error, and an invalid pin is a build error.
* Every patch (also the mechanism's own `R0M:*` rows) ends up in `anchors.json`; the gate fails on any count mismatch.

### What path-target patches see
Page-phase patches run on the tree AFTER the R0 mechanism, so anchor against that text, not against `baseline/dist`. **Line endings:** the baseline `index.html` is CRLF (production's file), and so are several other pages. Patch strings are authored with LF; when the target text is pure CRLF a string that contains only LF is converted to CRLF (`util.eol_adapt`, also used by the mechanism), a string that already contains a CRLF is used as written (the existing page patches for CRLF pages), and the asserted count stays strict. `index.html` of every train therefore has CRLF line endings only (T0-BL-07). Bundle targets (`js`, `help`, `book`, `css`) are LF and never adapted. Targets: `index.html` has no `modulepreload`, no CSS preload/`noscript`, only the `preconnect https://api.mapbox.com` hint, a `<meta name="color-scheme" content="dark" />` after `theme-color`, no `animation: boot-fade-in` in `#boot-splash`, the idle-registration script and the loader script (both from `mechanism/`), `<script defer src="/site-nav.js"></script>`, `<link rel="stylesheet" href="/assets/index-<css>.css" crossorigin />`; `site-nav.css` has no `body{animation}` fade; `sw.js`, `version.json` and `_ops/**` exist but are reserved.

### Overlay: `tools/t0/overlay/<dir>/**`
New or replacement files (binary ok), path relative to dist root. `R0` applies to every train, `R1a`/`R1b`/`R1c` to that train and later ones, `common` to R1a-R1c only (R0 is mechanism-only by D-ORDER; put a file in `overlay/R0` if it truly belongs there). Applied after the page phase, so an overlay file wins over a patched one; replacements are listed in `manifest.json` (`overlay[].replaced`). `README*` and `.gitkeep` are skipped. Overlay files under `assets/` are new asset names and go through the ledger.

### Config hook: `tools/t0/config/gen.mjs` (the real generator, R1c only; see `tools/t0/config/README.md`)
Receives `argv[2]` = dist path, `argv[3]` = JSON `{rid, entry, help, bookmark, css}`, env `T0_TRAIN` (and `T0_CONTEXT=staging` for a noindex tree). It reads the built pages and the entry bundle: the Street View sensor delegation on `/` is emitted whenever the bundle has the iframe `allow` attribute (every R1c build, so the Walkthrough logs no Google console error; the opt-in legal text says so on the privacy page, the baseline text is silent: `ops/header-decisions.md` sections 2 and 6). May write only `_headers`, `_redirects`, `netlify.toml`, `_ops/**`; the build diffs the tree and fails if anything else changed. Must be deterministic.

### Overlay merge guard
An overlay file may not REPLACE a file that production changed after the downloaded deploy (`baseline.lock.json` `changed_vs_legacy`: today `index.html` and `data/terrain.json`): the build fails with "merge it with a patch instead" (a replacement would silently revert live). Replacing a file production did not change (`manifest.json`, `screenshots/*`) is fine.

## The baseline (`baseline/`, `tools/t0/baseline.py`, `baseline.lock.json`)

Why: on 2026-09-30 a release verifier found that production no longer equals `legacy/dist` (docs/baseline-drift.md: `index.html` with three inline-script changes and CRLF line endings, `data/terrain.json` with eight corrected locations; neither exists in any of the 127 archived zips). The first four trains were built from the stale download and would have reverted both on deploy.

| path | what |
|---|---|
| `baseline/dist/` | the source-level tree of what production serves (119 files, tree `d2b126e9...3f727be6d`): `legacy/dist` with the two live files replaced; HTML reconstructed by undoing Netlify's post-processing |
| `baseline/live-2026-09-30/` | the evidence: `SHA256.tsv` (every response of the mirror), `headers.key.json` (non-volatile headers of 17 URLs), `MIRROR.json`, `RECONSTRUCTION.json`, `PROOF.json`, and `raw/` (git-ignored: bodies and all headers, they carry the RUM token) |
| `tools/t0/baseline.lock.json` | per-file sha256 of `baseline/dist`, tree digest, live deploy id at capture, `changed_vs_legacy` |
| `tools/t0/t0build/netlify.py` | the model of Netlify's HTML post-processing (RUM snippet before `</body>`; `<a href="/x.html">` becomes `<a href='/x'>` with sorted single-quoted attributes); JS mirror `forwardModel` in `ops/sha-list.mjs` |

```
python tools/t0/baseline.py verify-live     # production vs baseline/dist: IDENTICAL (exit 0) | DRIFTED + per-file diff (1) | could not run / baseline altered (2)
python tools/t0/baseline.py verify          # baseline/dist vs the lock (the build does this too)
python tools/t0/baseline.py mirror          # fetch production (curl, identity encoding, cache-busted, both URL forms of every page) into baseline/live-2026-09-30/raw
python tools/t0/baseline.py reconstruct     # raw -> baseline/dist (non-html as served; html with post-processing undone against legacy/dist as reference)
python tools/t0/baseline.py prove           # model(baseline/dist) == every served response, byte for byte
python tools/t0/baseline.py lock            # write the lock
# mirror refuses an existing mirror folder without --force; reconstruct refuses to replace the locked baseline/dist without --replace
python tools/t0/baseline.py compare-legacy  # every difference between legacy/dist and baseline/dist (source-level diff)
```
`verify-live` compares non-HTML files byte for byte and HTML pages through the model, expects `/diagnostics.html` to answer 404 (forced redirect in `netlify.toml`) and the config files not to be served, finds files that live serves and references but the baseline lacks, and reports header drift against the snapshot. Procedure when it says DRIFTED: `ops/RELEASE-RUNBOOK.md` section 15.

## Gates (`gate.mjs`, `release/<train>/gate.json`)

| id | checks |
|---|---|
| `parse` | acorn parse of every `.js` (module for `assets/`, script-then-module elsewhere) and every inline `<script>`; only NEW failures vs the baseline fail |
| `unresolved-globals` | eslint-scope: bare-name references that resolve to no declaration in entry/Help/Bookmark vs the legacy chunks. `setGoldUnit clearGoldTrail drawGoldTrailSegment CanvasRenderer` must be gone exactly when group A is in (R1a+) and untouched in R0; no other new names except the standard globals in `browser-globals.json` (`matchMedia`, `sessionStorage` ... are used by group C) |
| `anchors` | reads `anchors.json`: every patch found exactly `expect` times |
| `ledger` | every `assets/*` name vs `ops/used-names.txt` (case-insensitive): same name must keep its bytes, a new name must not collide with any archived name |
| `references` | every `/assets/x` string in any html/js/css/json/toml/_headers file, every relative `"./x.js"` import in assets, every local `<script src>/<link href>/<img src>` and manifest icon/screenshot resolves to a file; only NEW dangling refs fail |
| `no-legacy-asset-names` | none of the five legacy asset names is referenced or present (outside the ledger copy) |
| `r0-mechanism` | sentinel, `version.json` <-> files, `sw.js` (no `skipWaiting(`, claims, cache name, bails on navigations), `index.html` (loader names the entry, no `controllerchange`, no `modulepreload`, no fade, `site-nav.js` deferred), `asset-manifest.json` lists exactly `assets/`, NO `sw-kill.js` inside the dist and the copy beside it (`<out>/_ops/sw-kill.js`) == `ops/sw-kill.js`, `node --check` of `sw.js` and `ops/sw-kill.js` |
| `no-owner-notes` | no shipped text file contains an owner-review marker (`OWNER TO CONFIRM`, `OWNER REVIEW REQUIRED`, `[[WHEN SHIPPED]]`), in a comment or not |
| `legacy-pinned` | `legacy/dist` (the downloaded deploy) still hashes to the pinned tree digest (119 files) |
| `baseline-pinned` | `baseline/dist` matches `baseline.lock.json` (per-file sha256, tree digest) |
| `data-untouched` | no `data/*` file of the BASELINE tree is modified or removed (T0 rule 5); added files are listed, not failed |
| `bytes` | total / per-directory / biggest files, delta vs legacy, entry size + brotli size |

## The used-names ledger (`ops/used-names.txt`)

TSV `name  sha256  bytes  zips  first-source`, seeded by `python tools/t0/ledger.py seed` from **every** file that sits in an `assets/` folder inside the 127 archived zips (`C:/Users/mlege/gettysburg-archive/zips`, python `zipfile`) plus `legacy/dist` (157 name/bytes pairs; `index-Cg8FAMXN.js` carries 45 byte streams, as chapter 02 says). The build refuses to publish a name that was published with different bytes and any new name that collides with an archived one. `_ops/used-names.txt` in dist is the ledger plus that train's names (archive file names are replaced by the word `archive`; the dist is public). After a **deploy** (owner step) run `python tools/t0/ledger.py record --dist release/R1a/dist --train R1a --rid <rid>` and commit `ops/used-names.txt`; `build.py --record` does the same at build time.

## Kill switch and rollback

`ops/sw-kill.js` (an identical copy sits at `release/<train>/_ops/sw-kill.js`, deliberately outside the dist and never served): deploy it AS `/sw.js` (level L2). Tested by `T0-R0-06` including "no reload loop when the page re-registers it". Level L1 is Netlify "Publish deploy" of the previous deploy; old asset names still exist in old deploys. Note for deploys: `dist/netlify.toml` is the legacy file (`publish = "."`, the current headers); the Netlify CLI takes the toml from the working directory, not from `--dir`, so a CLI deploy needs a repo-root `netlify.toml` (owner/WP-T0-02) or the R1c `_headers` output.
