# Tranche-0 tooling and release content: change log

Scope: `tools/t0/` (build system, patch groups, overlay, config generator, baseline tooling), `tests/t0/` (harness and suites), `baseline/` (the live-site
baseline), `ops/` (runbooks, probes) as they stand after the re-baseline of 2026-09-30 (newest entry first). Nothing here has been deployed. Plan: `docs/plan/FINAL/02-tranche0-hotfix-runbook.md`
(chapter 02) and `docs/plan/FINAL/01-decision-register.md`. Per-train release notes: `ops/release-notes/<train>.md`
(also `release/<train>/RELEASE-NOTES.md`, generated by `python tools/t0/release_notes.py`).

## 2026-09-30 (later) - re-baseline on the live site (train set unchanged: R0 fb14ab00, R1a 740deb52, R1b 8ad6d7cd, R1c 9feb2ee6)

A release verifier found that production no longer equals `legacy/dist` (the downloaded deploy 6aa16d61): the live deploy `6abd6d62...` changed
`index.html` and `data/terrain.json`, and neither version is in any of the 127 archived zips. The four trains above had been built from the stale
download; deploying any of them would have reverted both files. Full account: `docs/baseline-drift.md`. This entry lists what changed in the tooling.

1. **Mirror and baseline.** `python tools/t0/baseline.py mirror` fetched production (147 requests, curl, identity encoding, cache-busted, both URL forms of
   every page; 144 x 200, 3 x 404 as expected); `reconstruct` wrote the source-level tree `baseline/dist` (117 files identical to `legacy/dist`, 2 from live:
   `index.html` [3 inline-script changes, CRLF] and `data/terrain.json` [8 key locations moved 166-734 m, CRLF]); `prove` showed that the model of Netlify's
   post-processing (`t0build/netlify.py`: RUM snippet before `</body>`, `<a href="/x.html">` -> `<a href='/x'>` with sorted single-quoted attributes) applied to
   `baseline/dist` gives every served page (27, both URL forms) and file (91 non-HTML) byte for byte; `netlify.toml` is not served and cannot be compared.
   Evidence in `baseline/live-2026-09-30/` (`SHA256.tsv`, `headers.key.json`, `MIRROR.json`, `RECONSTRUCTION.json`, `PROOF.json`; `raw/` is git-ignored).
2. **Build rebased.** `trains.json` gains `base` (`dir baseline/dist`, `lock tools/t0/baseline.lock.json`); `build.py` pins the baseline per file, refuses a
   differing baseline (exit 2, names the file), still checks `legacy/` is unmodified, records the baseline tree in `manifest.json`; `gate.mjs` gets
   `baseline-pinned` and compares `parse`/`unresolved-globals`/`ledger`/`references`/`data-untouched`/`bytes` against the baseline; `verify_release.mjs` V6
   (identity) compares with the baseline and has a new V8 (baseline lock, trains built from the locked baseline, drift = exactly the locked files). `overlap.py`,
   `ledger.py` and the bundle pins still read the unchanged bundle texts.
3. **CRLF.** The live `index.html` is CRLF. Patch strings are LF-authored; `util.eol_adapt` converts an LF-only string to CRLF when the target is pure CRLF
   (patch applier and R0 mechanism); strings with an explicit CRLF (the existing patches of the CRLF pages) are untouched; counts stay strict. Every train's
   `index.html` is CRLF only (T0-BL-07).
4. **Re-anchoring.** No anchor moved: all 16 R0 mechanism rows and the 37 `index.html` anchors of R1c matched with their asserted counts after the CRLF
   adaptation; every other group (A, B, DL, C, AX, CP including the Help-chunk rows, PG-core, PG-maps, PG-legal) targets files production did not change; the
   config generator reads no baseline file that changed. Release ids are unchanged (they hash the bundle texts). New patch `C:live-hide-legacy-bar-superseded`
   (`tools/t0/patches/C+baseline.json`): group C removes the live inline block that hides the legacy desktop timeline bar in Mobile mode (R1b and R1c; kept in
   R0/R1a where the legacy bar is mounted in Mobile mode). Counts: R0 22, R1a 242, R1b 376 (+1), R1c 426 (+1). The star-marker Monuments overlay that
   production removed is gone from R1b/R1c as well (they shipped it before).
5. **Overlay guard.** An overlay file may not replace a file listed in the lock's `changed_vs_legacy`; the build tells you to merge with a patch. No overlay file
   touches `index.html` or `terrain.json`.
6. **verify-live.** `python tools/t0/baseline.py verify-live`: IDENTICAL (0) / DRIFTED with per-file source-level diff (1) / could not run or baseline altered (2).
   Handles both URL forms, the forced-404 `/diagnostics.html`, unserved config files, files that live serves and references but the baseline lacks, header
   drift against the snapshot (HSTS by max-age only), network errors (retry, then exit 2; never read as drift). `mirror` and `reconstruct` refuse to overwrite
   committed evidence / the locked baseline without `--force` / `--replace`. `ops/sha-list.mjs verify-url` gets `--tree <source dir>` (JS mirror of the model
   explains RUM and link rewriting; any other html difference is DIFF); `--html-warn` is ignored (it hid real content drift).
7. **Tests.** New `tools/t0/tests/baseline_selftest.py` (16 cases; fake Netlify on `T0_PORT_BASE`+9) and `tools/t0/tests/baseline-drift.spec.mjs` (T0-BL-01..09);
   `run_suites.mjs` rows `static.baseline`, `static.baselinelock`, `baseline.drift`, `baseline.live` (`--no-network` skips it); red-first proofs stay on
   `legacy/dist` (the specs recognise "legacy" by that path). `tests/t0/*` and `package.json` were not edited by this work.
8. **Docs.** `docs/baseline-drift.md`; `ops/RELEASE-RUNBOOK.md` rule 11, section 4.1, step 7.0 and section 15 (live drifted procedure); `ops/STAGING-SETUP.md`
   (identity proof on `baseline/dist` with `--tree`); `ops/RELEASE-LOG.md` and `ops/owner-console-actions.md` (rollback target `6abd6d62...`, archive the live
   deploy); `tools/t0/README.md`; release notes (`release_notes.py`: baseline input, "Live drift carried by this train").
9. **Line endings of the tooling files.** An editing slip converted several tooling files to CRLF; they were restored to LF (`.gitattributes` is `* -text`, so
   git does not normalise).

Test results of the rebuilt trains (`node tools/t0/run_suites.mjs`, port base 8600, 2026-09-30; `ops/release-notes/test-results.json`): **40/40 suites OK,
415 green tests (23 more skipped by design: tests of groups a train does not contain, A11Y-14 runs as its own suite), 8/8 red-first proofs on `legacy/dist` (58
legacy tests red as required)**; 16/16 `baseline_selftest`, 9/9 T0-BL, `verify-live` IDENTICAL (exit 0) as the last row. The first pass of the table had one red
suite, `pagesmaps.R1c` PG-02-camera, a timing assertion (first contentful paint 3,120 ms against a Mapbox library held back 3,000 ms, so 34 ms apart) that lost the race
on a machine loaded by other agents' processes; it passed 34/34 on re-run on the same tree (`--merge` into the summary), and the page is byte-identical to the previous
run's. Build output of this work compared with the previous trains: `release/R0..R1c` differ in `index.html` and `data/terrain.json` only (R1b and R1c
`index.html` additionally lose the superseded blocks).

## 2026-09-30 - integration (train set R0 fb14ab00, R1a 740deb52, R1b 8ad6d7cd, R1c 9feb2ee6)

Built all four trains from scratch (`python tools/t0/build.py --all`), gates green, rebuilt twice into different directories: every file of
every dist is byte-identical (sha256), as are `anchors.json` and `manifest.json` (`tmp`-level comparison; `build_selftest` case 1 proves the
same for R1c on every run). Changes made by the integrator to files owned by the group agents:

1. `tests/t0/build_selftest.py` case 6 (plugin interface): its throwaway `PG-selftest` group deleted `diagnostics.html` and
   `unit-rendering-reference.html`, which the real `PG-core` already deletes ("file to delete does not exist"). It now deletes
   `apple-touch-icon-precomposed.png`, which no real group removes. The case still proves placeholders, delete, overlay new + replace, the
   hook whitelist and four negative cases. `tools/t0/build.py` no longer prints the hard-coded `release/<train>/anchors.json` in its
   anchor-failure message (it prints the real output path).
2. Group EB removed. The AMD-T0-1 error boundary is patch `A-error-boundary` in `A.json` (the owner authorized the full plan); `EB.json` anchored
   on the same text and failed (`expected 1, found 0`). `trains.json` `optional_groups` is now `[]`; `--with GROUP` stays for future use
   (`build.py`, `overlap.py`, README updated).
3. `trains.json` `known_overlaps` now records the four ordered dependencies the overlap audit flagged: AX anchors on group C output
   (`AX-mobile-map-id`, `AX-mobile-dock-id`), CP anchors on group C output (`cp:mobile-tools-footer`), and the adjacent finds `bug:K-skip-tour`
   (A) / `AX-onboarding-dialog` (AX), which share `V.jsx("div",{style:tr.overlay` that A's replacement keeps, so either order matches
   (`build_selftest` case 5 builds both orders and compares the bytes). `python tools/t0/overlap.py` reports 0 unexplained overlaps.
4. `data/moments.json` moved from `overlay/common` (shipped from R1a) to `overlay/R1c`: nothing in R1a/R1b reads it, and the plan files moments
   v0 under R1c (WP-T0-09). R1a and R1b lost one file (124 files each); R1c is unchanged.
5. `tests/t0/mobile-matrix.spec.mjs` T0-MOB-09 (popup over the story cards): the test computed the tick-12 position of U-CAV-1-1 from
   `placements_day1_ticks1_50.json` only. With group B (R1c) the unit is correctly held at its latest keyframe at or before the tick, which is the
   tick-9 row in `density_day1_opening.json`, so the tap missed on R1c while it passed on R1b (bisected by building R1c with each of B, DL, CP
   emptied: only B changes it). The test now tries every keyframe at or before tick 12, latest first. Product code is untouched.
6. `tests/t0/mobile-matrix.spec.mjs` T0-MOB-05 and `tests/t0/r0.mjs` T0-R0-03 counted Chrome's own cache revalidation as a second Mapbox style request: the style JSON is served with
   `Cache-Control: max-age=900, stale-while-revalidate=3600`, so once the copy in the session's HTTP cache has expired Chrome answers the page's fetch
   from the cache and sends one background revalidation (resource type `Other`, about 20 ms later, same frame, same sku). It made MOB-05 fail on R1b
   in two consecutive four-slice runs (different viewports each time; four parallel sessions hit it at the same load number) and never in a
   single-session run. Reproduced with `tmp`-level probes (same two requests in all four sessions, `Fetch` then `Other`, `max-age=900` header seen).
   Both tests now count only the page's own requests (`type !== 'Other'`). A real second map would still show as a second `Fetch` and a second sku.
7. `tools/t0/run_suites.mjs` red-first rules: a red proof needs at least one FAILED test and no skipped one
   (a spec that skips on legacy proves nothing), and specs that assert the red state themselves under `--expect-red` (a11y, copy) are marked `inverted`.
8. New tools: `tools/t0/verify_release.mjs` (independent check of the four trains: manifest, static crawl with no dangling reference, dev pages,
   asset-name ledger across trains, identity invariants of rule 5, cumulative trains, legacy pinned), `tools/t0/run_suites.mjs` (every suite and
   the red-first proofs, one summary JSON), `tools/t0/release_notes.py` (the notes), `package.json` scripts (`t0:verify`, `t0:test:all`, `t0:test:*`,
   `t0:notes`), README and this change log.
