## 2026-10-01 (perf round 2) - Mapbox shader programs requested before their first draw (R0 extension part), R0 mobile Lighthouse 85 -> 94, R1c TBT 440 -> 154 ms

Goals of the a11y/perf verifier's defects (R0 below the plan's mobile 85, TBT 420-650 ms, render-blocking CSS, CLS without headroom, duplicate fetches, the reload-alone claim): CLS, render-blocking CSS and the reload-alone note were settled in the first perf round (PERF group, banner row; runbook 14.19-14.20); this round found what the TBT really was and removed it.

1. **New `tools/t0/patches/R0+mapbox-precompile.json`** (extension part of group R0, patch `R0-mapbox-precompile (perf)`, runbook 14.21 and B.8, every train): `gtPrecompile(map)` is called at the end of `T4` (the function that adds the app's layers) and makes Mapbox's own precompiler (`style._programPrecompiler`) create the programs of those layers, plus the text/SDF symbol program it cannot derive, in one short task right after the next style update, so the GPU process links them while the main thread is free instead of the first frames blocking in `Program._finalize` (symbol 80-100 ms, line 14-20 ms each in the software-GL lab). Does nothing without `KHR_parallel_shader_compile`, on a removed or re-styled map, or when a private field is missing (try/catch, bundle pinned to Mapbox 3.24.1). R0's release id changes (54e21b2e on the tree of this entry); nothing else in R0 moves (121 files, 24 anchor records).
2. **Measured** with the exact control (the same tree built with `--patches` pointing at a copy of `tools/t0/patches` without the file), Lighthouse 13.5, real tiles, mobile n = 7 interleaved on a quiet host: R0 85 -> 94, R1a 84 -> 92, R1b 91 -> 98, R1c 89 -> 98; TBT 590 -> 286, 665 -> 345, 383 -> 161, 440 -> 154 ms; desktop 100 -> 100 with TBT 29-44 -> 0 ms; full-page screenshots after idle identical. Numbers, the experiments that were tried and dropped (including the Map constructor in its own task and the PERF stylesheet rows on R0, both re-tested), and what could not be verified are in `ops/release-notes/perf-results.json` (`round2`) and runbook 14.21. TBT < 200 ms holds on R1b and R1c; R0 and R1a (286-345 ms) need the rebuild.
3. **Tests:** `tests/t0/perf-fixes.spec.mjs` PF-07 (Mapbox's compile statistics of a real boot, phone and desktop viewport), PF-08 (lines and labels still rendered), PF-09 (unit tests of `gtPrecompile` against fake maps incl. the no-parallel-compile guard), PF-10 (the extension hidden by an init script: boots and draws, nothing precompiled); PF-07..09 red on the tree without the patch (`--expect-red`, and `--behavior-only` for PF-07). R0 4/4 (+6 skipped by design), R1a 9/10 (+1), R1b and R1c 10/10; `r0.mjs` 13/13; journeys 41/41 (R1c), deeplinks 12/12, map pages 34/34, a11y real tiles 1/1, mobile matrix portrait 6/6 and touch 3/3; two builds of R0 and R1c byte-identical.

## 2026-10-01 (release-verifier fixes, second round) - default Walkthrough sensors, stale-dist guard, verify-url exit, emulator fidelity

Second pass over verifier 3's defects 2-11 against the tree as it stands (every item re-run, not re-read). Findings and what changed:

1. **The default R1c build logged Google's accelerometer error.** The first round delegated accelerometer + gyroscope to the Street View frame only when `privacy.html` disclosed it, i.e. only
   in a build made with the opt-in legal text, so a plain `build.py --all` still shipped the error. Now `config/gen.mjs` delegates whenever the entry bundle carries the iframe `allow`
   attribute (every R1c build); the privacy statement is checked the other way round (a page that claims the delegation without the attribute is untrue: generator warning, `verify-facts`
   FAIL; the silent baseline text next to a delegating header is one owner-visible `WARN`, printed by `staging-verify` S10). Proven on the real Google embed on the DEFAULT build:
   `HDR-23` (`--online`) and `ops/walkthrough-policy-experiment.mjs asbuilt --inject` log 0 messages. `HDR-07/13/24` and probe `E-03` follow the new rule; `HDR-24` also builds an
   attribute-less copy and requires `/` to stay off. Decision record: `ops/header-decisions.md` sections 2, 5, 6; `ops/T0-DEVIATIONS.md` row 2.
2. **`release/` goes stale and nothing noticed.** The ignored `release/R1c/dist` of the working tree still held the pre-fix build (owner-note comments, public `_ops/sw-kill.js`), consistent
   with its own manifest and gate. `ops/staging-verify.mjs` S0 now rebuilds the train (same optional groups) into `tmp/staging-verify-rebuild/` and requires the same tree digest
   (`STALE dist` otherwise); `--no-rebuild` skips it, `--only S0,S2` runs chosen steps and labels the run partial. Self-test case 10.
3. **`ops/sha-list.mjs verify-url` aborted Node on Windows** (`Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`, exit 127, also when every file matched) because it called
   `process.exit()` while keep-alive sockets were closing; it now sets `process.exitCode`. Self-test case 9 (identical tree: 0, changed html file: `DIFF` and 1) was red on the old code.
4. **Emulator content types.** `config/emulate.mjs` answered `text/javascript`, `application/json; charset=utf-8` and `image/x-icon`; production answers `application/javascript; charset=UTF-8`,
   `application/json`, `image/vnd.microsoft.icon` (measured). A `--parity` run of an emulated R0 against production failed on 5 of 16 URLs; after the fix R0, R1a and R1b show
   `PASS PARITY  16 representative URLs ...` against the real site (new row in `tools/t0/config/README.md`, "Emulated rules"; `HDR-10` asserts the table).
5. **Runbook** (`ops/RELEASE-RUNBOOK.md`, `ops/STAGING-SETUP.md`) re-read command by command a third time: numbers that move with every patch (R0 file count, bytes, tree digest) are dated
   examples now, S0/S10 and the rehearsal evidence are described, the verify-live timing and the L2 PowerShell form were re-measured.
6. **Not done here, needs the integrator:** the ignored `release/*` folders and the committed `ops/release-notes/*.md` (still say that `PG-legal` ships by default and quote the old release ids)

## 2026-09-30 (later) - re-baseline on the live site (train set unchanged: R0 fb14ab00, R1a 740deb52, R1b 8ad6d7cd, R1c 9feb2ee6)

A release verifier found that production no longer equals `legacy/dist` (the downloaded deploy 6aa16d61): the live deploy `6abd6d62...` changed
`index.html` and `data/terrain.json`, and neither version is in any of the 127 archived zips. The four trains above had been built from the stale
download; deploying any of them would have reverted both files. Full account: `docs/baseline-drift.md`. This entry lists what changed in the tooling.

1. **Mirror and baseline.** `python tools/t0/baseline.py mirror` fetched production (147 requests, curl, identity encoding, cache-busted, both URL forms of
   every page; 144 x 200, 3 x 404 as expected); `reconstruct` wrote the source-level tree `baseline/dist` (117 files identical to `legacy/dist`, 2 from live:
   `index.html` [3 inline-script changes, CRLF] and `data/terrain.json` [8 key locations moved 166-734 m, CRLF]); `prove` showed that the model of Netlify's
   post-processing (`t0build/netlify.py`: RUM snippet before `</body>`, `<a href="/x.html">` -> `<a href='/x'>` with sorted single-quoted attributes) applied to
   `baseline/dist` gives every served page (27, both URL forms) and file (91 non-HTML) byte for byte; `netlify.toml` is not served and cannot be compared.
   Evidence in `baseline/live-2026-09-30/` (`SHA256.tsv`, `headers.key.json`, `MIRROR.json`, `RECONSTRUCTION.json`, `PROOF.json`; `raw/` is git-ignored).
2. **Build rebased.** `trains.json` gains `base` (`dir baseline/dist`, `lock tools/t0/baseline.lock.json`); `build.py` pins the baseline per file, refuses a
   differing baseline (exit 2, names the file), still checks `legacy/` is unmodified, records the baseline tree in `manifest.json`; `gate.mjs` gets
   `baseline-pinned` and compares `parse`/`unresolved-globals`/`ledger`/`references`/`data-untouched`/`bytes` against the baseline; `verify_release.mjs` V6
   (identity) compares with the baseline and has a new V8 (baseline lock, trains built from the locked baseline, drift = exactly the locked files). `overlap.py`,
   `ledger.py` and the bundle pins still read the unchanged bundle texts.
3. **CRLF.** The live `index.html` is CRLF. Patch strings are LF-authored; `util.eol_adapt` converts an LF-only string to CRLF when the target is pure CRLF
   (patch applier and R0 mechanism); strings with an explicit CRLF (the existing patches of the CRLF pages) are untouched; counts stay strict. Every train's
   `index.html` is CRLF only (T0-BL-07).
4. **Re-anchoring.** No anchor moved: all 16 R0 mechanism rows and the 37 `index.html` anchors of R1c matched with their asserted counts after the CRLF
   adaptation; every other group (A, B, DL, C, AX, CP including the Help-chunk rows, PG-core, PG-maps, PG-legal) targets files production did not change; the
   config generator reads no baseline file that changed. Release ids are unchanged (they hash the bundle texts). New patch `C:live-hide-legacy-bar-superseded`
   (`tools/t0/patches/C+baseline.json`): group C removes the live inline block that hides the legacy desktop timeline bar in Mobile mode (R1b and R1c; kept in
   R0/R1a where the legacy bar is mounted in Mobile mode). Counts: R0 22, R1a 242, R1b 376 (+1), R1c 426 (+1). The star-marker Monuments overlay that
   production removed is gone from R1b/R1c as well (they shipped it before).
5. **Overlay guard.** An overlay file may not replace a file listed in the lock's `changed_vs_legacy`; the build tells you to merge with a patch. No overlay file
   touches `index.html` or `terrain.json`.
6. **verify-live.** `python tools/t0/baseline.py verify-live`: IDENTICAL (0) / DRIFTED with per-file source-level diff (1) / could not run or baseline altered (2).
   Handles both URL forms, the forced-404 `/diagnostics.html`, unserved config files, files that live serves and references but the baseline lacks, header
   drift against the snapshot (HSTS by max-age only), network errors (retry, then exit 2; never read as drift). `mirror` and `reconstruct` refuse to overwrite
   committed evidence / the locked baseline without `--force` / `--replace`. `ops/sha-list.mjs verify-url` gets `--tree <source dir>` (JS mirror of the model
   explains RUM and link rewriting; any other html difference is DIFF); `--html-warn` is ignored (it hid real content drift).
7. **Tests.** New `tools/t0/tests/baseline_selftest.py` (16 cases; fake Netlify on `T0_PORT_BASE`+9) and `tools/t0/tests/baseline-drift.spec.mjs` (T0-BL-01..09);
   `run_suites.mjs` rows `static.baseline`, `static.baselinelock`, `baseline.drift`, `baseline.live` (`--no-network` skips it); red-first proofs stay on
   `legacy/dist` (the specs recognise "legacy" by that path). `tests/t0/*` and `package.json` were not edited by this work.
8. **Docs.** `docs/baseline-drift.md`; `ops/RELEASE-RUNBOOK.md` rule 11, section 4.1, step 7.0 and section 15 (live drifted procedure); `ops/STAGING-SETUP.md`
   (identity proof on `baseline/dist` with `--tree`); `ops/RELEASE-LOG.md` and `ops/owner-console-actions.md` (rollback target `6abd6d62...`, archive the live
   deploy); `tools/t0/README.md`; release notes (`release_notes.py`: baseline input, "Live drift carried by this train").
9. **Line endings of the tooling files.** An editing slip converted several tooling files to CRLF; they were restored to LF (`.gitattributes` is `* -text`, so
   git does not normalise).
