# POLISH - the final polish pass (optional patch group, four files)

Status: built and proven on scratch trees of R1c + CLOCK + DATA + MON (`tmp/polish/stack`) and R1c + CLOCK + DATA + MON + ANIM (`tmp/polish/pa`), 2026-10-20. **Not registered** in `trains.json`, not in `release/`, nothing deployed; no existing file was edited. It fixes the five defects an independent reviewer found on the R1c production build and the same kind of defect around them.

Files (inert, in `tools/t0/patches-next/`): `POLISH.json` (bundle part, 9 patches), `POLISH+mon.json` (extension part, valid only with MON, 2 patches), `PG-polish.json` (page part, 42 patches), `PG-polish-legal.json` (optional companion page group, only for a build that also uses `PG-legal`, 8 patches). Tests: `tests/t0/polish.spec.mjs` (13 ids; T0-POL-13 is the reachability of the guide and Toggle Units, section 3b) and the six existing specs whose expectations were updated (section 6).

## One deviation from "one group file": the page half is a page group

The builder applies the page patches of the fixed groups BEFORE the page groups (`patches.apply_page_phase`: fixed groups in order, then `PG-*` sorted), and `PG-core` / `PG-maps` rewrite `index.html`, `historian.html`, `search.html` and others. A page patch inside `POLISH.json` must match the pre-PG text and, for the menu button, removes `<span>Extra Features</span>`, which `PGC-index-use-menu` still anchors on (tried: the build fails). Anchoring on the finished page text needs a page group, so the page half is `PG-polish.json` (`"optional": true`, `"train": "R1c"`, built with `--with PG-polish`, the same mechanism as `PG-legal`). The three files are one logical group: register all or none (`PG-polish-legal.json` is a fourth, optional one: register it only together with `PG-legal`, see section 6). If the integrator would rather keep a single file, the alternative is to edit `PGC-index-use-menu` (not allowed here).

## Build and prove

```
python tmp/polish/stack.py --out tmp/polish/stack --with CLOCK,DATA,MON,POLISH,PG-polish          the tree (30 s)
python tmp/polish/stack.py --out tmp/polish/pa    --with CLOCK,DATA,MON,ANIM,POLISH,PG-polish     with ANIM
python tmp/polish/stack.py --out tmp/polish/base  --with CLOCK,DATA,MON                           the control: the same tree without POLISH
node tests/t0/polish.spec.mjs --dist tmp/polish/stack/dist --control tmp/polish/base/dist --build [--quick] [--filter 'POL-0[2-4]']
node tests/t0/polish.spec.mjs --dist tmp/polish/base/dist --expect-red                            red-first: the control must FAIL
```
`tmp/polish/stack.py` is a git-ignored scratch wrapper (it copies `patches/` plus the named `patches-next` files, parts included, to a stage directory and calls `build.build_train` with `optional_groups` extended in memory, like `data_build.py`/`anim_build.py`, which cannot be used because they copy only `<group>.json` and would apply `PG-polish` as a fixed group). T0-POL-12 (`--build`) does the same with an inline Python call, so the test does not depend on `tmp/`.
